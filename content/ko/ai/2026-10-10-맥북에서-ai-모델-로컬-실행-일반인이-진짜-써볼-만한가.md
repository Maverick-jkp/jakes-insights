클라우드 AI 비용이 슬금슬금 오르고 있어요. Anthropic은 2026년 6월 15일부로 에이전트 SDK 크레딧 청구 방식을 분리했고, OpenAI도 API 요금 구조를 계속 손보는 중이에요. 이 시점에 "그냥 내 맥북에서 직접 돌리면 안 되나?"라는 생각이 드는 건 자연스러운 흐름이에요. 그런데 맥북에서 AI 모델 로컬 실행—일반인이 진짜 써볼 만한가, 이 질문에 대한 답은 생각보다 훨씬 조건부예요.

> **핵심 요약**
> - macOS의 메모리 제한으로 36GB RAM 맥도 LLM에 실제 쓸 수 있는 건 약 24GB뿐이며, 30B 이상 풀정밀 모델은 현실적으로 64GB가 필요하다.
> - [메일리의 21일 PoC 리포트](https://maily.so/yihyunai/posts/l1zqypqnr5x)에 따르면, 벤치마크 1위(Gemma 4 31.3B)는 응답 시간이 1~2분으로 실사용 불가였고, 실제 채택된 모델은 성능 타협 없이 속도를 잡은 Gemma 26B Q4였다.
> - 7~8B 모델은 8GB RAM 맥북에서도 돌아가며, 반복적·일상적 텍스트 작업의 약 95%를 커버할 수 있다.
> - 로컬 실행의 핵심 이점은 '무한 사용, 무비용, 데이터 외부 전송 없음'이지만, 복잡한 추론·긴 문서 분석에서는 클라우드 모델에 여전히 뒤처진다.

## 애플 실리콘이 바꾼 판

맥에서 AI를 로컬로 돌리는 건 2023년만 해도 꽤 특이한 시도였어요. GPU 전용 메모리가 따로 없으면 성능이 너무 떨어졌거든요. 그런데 애플 실리콘의 유니파이드 메모리 구조가 이 판을 바꿨어요. CPU와 GPU가 RAM을 함께 쓰는 구조라, 같은 용량 대비 LLM 처리에 훨씬 유리해요.

[TypeTab의 분석](https://typetab.app/blog/local-llms-on-your-mac)에 따르면, 4비트 양자화 기준으로 필요한 메모리는 이렇게 정리돼요:

- **1~3B 모델**: 1~2GB → M1 맥북 에어 포함 전 모델 가능
- **7~8B 모델**: 4~5GB → 8GB RAM 이상
- **14B 모델**: 약 9GB → 16GB RAM 이상
- **70B+ 모델**: 40GB+ → 64GB RAM 필요

실제로 2020년 M1 맥북 에어도 7~8B 모델은 충분히 돌아가요. 하드웨어 측면만 보면 문턱이 생각보다 낮은 편이에요.

도구는 두 가지가 주류예요. **Ollama**는 커맨드라인 기반 오픈소스로, `ollama run llama3.2` 한 줄로 시작해요. **LM Studio**는 GUI 기반에 모델 브라우저까지 갖춘 무료 앱이에요. 두 도구 모두 Llama, Mistral, Gemma 같은 모델을 동일하게 실행하고, 차이는 인터페이스뿐이에요.

## 21일 실전 테스트: 숫자가 보여주는 현실

그럼 실제로는 어떨까요.

[메일리의 로컬 LLM 도입기](https://maily.so/yihyunai/posts/l1zqypqnr5x)는 Mac Studio M4 Max(36GB RAM, 약 300만 원대)에서 Ollama 0.23.2 백엔드로 6개 모델을 21일간, 25점 만점 4단계 검증으로 테스트한 결과예요.

| 모델 | 점수 | 채택 여부 |
|------|------|----------|
| Gemma 4 31.3B | 25/25 | ⛔ 속도 문제로 탈락 |
| Qwen 3.6 27.8B | 24/25 | ✅ 권장 |
| Qwen 3.6 36.0B | 23/25 | ✅ 권장 |
| Gemma 4 26B Q4 (Unsloth) | — | ✅ **최종 채택** |
| Granite 4.1 28.9B | 17/25 | ⛔ 탈락 |

벤치마크 1등인 Gemma 4 31.3B가 탈락한 이유는 단순해요. 응답 시간이 **1~2분**이었어요. 에이전트 파이프라인에서 이 속도는 실사용 불가 판정이에요. 최종 채택된 건 Gemma 26B Q4(Unsloth Dynamic 양자화) + 4비트 KV 캐시 조합이에요. 성능보다 속도와 메모리 효율을 먼저 본 거죠.

### 메모리 함정: 36GB인데 실제론 24GB

많은 사람이 놓치는 포인트가 있어요. macOS 시스템이 메모리 일부를 점유하기 때문에, 36GB RAM이어도 LLM에 실제로 쓸 수 있는 건 약 **24GB**예요. Hermes(에이전트)와 OpenWebUI를 동시에 돌리면 이 한계를 쉽게 넘어요. 최종 설정은 약 15GB 여유를 남기는 방식으로 구성됐어요.

30B 이상 모델을 풀정밀(FP16)로 돌리려면 현실적으로 64GB RAM이 필요해요. M4 Max 기준으로도 128GB 옵션이 있지만, 가격이 완전히 다른 얘기가 돼요.

### 로컬 vs. 클라우드: 솔직한 비교

| 항목 | 로컬 실행 | 클라우드 API |
|------|----------|------------|
| 비용 | 초기 하드웨어 후 무료 | 사용량 비례 과금 |
| 속도 | 모델 크기에 따라 느림 | 일반적으로 빠름 |
| 프라이버시 | 데이터 외부 전송 없음 | 서버 전송 필요 |
| 복잡한 추론 | 클라우드 대비 약함 | GPT-4o, Claude 수준 |
| 사용 제한 | 없음 | Rate limit 존재 |
| 설치 난이도 | 중간 (도구 설치 필요) | API 키만 있으면 됨 |

TypeTab의 분석이 제시하는 프레임은 명확해요. **복잡한 작업의 약 5%는 클라우드, 반복·일상적 텍스트 작업의 95%는 로컬**이 더 적합해요. 자동완성, 파일 검색, 간단한 요약—이런 게 로컬 모델의 진짜 쓰임새예요.

## 일반인 기준: 어떤 맥북, 어떤 용도

**8GB 맥북 에어 / M1~M3 계열**
7~8B 모델까지 가능해요. Llama 3.2 8B, Gemma 3 8B 정도가 현실적인 선택이에요. 일상 대화, 간단한 요약, 코드 자동완성 정도는 충분히 돼요. 단, 멀티 앱 동시 사용 시 버벅임이 생길 수 있어요.

**16GB 맥북 프로 / M3 Pro 이상**
14B 모델까지 쾌적하게 돌아가요. Qwen 2.5 14B 같은 모델은 한국어 품질도 꽤 괜찮아요. 개발자 도구나 로컬 에이전트 실험 용도로 쓰기 좋은 구성이에요.

**36GB Mac Studio M4 Max**
이 리포트의 테스트 환경이지만, 실제 쓸 수 있는 건 24GB 수준이에요. 27~30B 양자화 모델이 현실적이고, 에이전트 파이프라인까지 붙이면 메모리 계획이 필수예요.

## 써볼 만한 사람, 아직 이른 사람

**지금 당장 써볼 만한 경우:**
- API 비용이 월 5만 원 이상 나오는 개발자나 헤비 유저
- 민감한 문서(계약서, 의료 기록 등)를 AI로 처리하고 싶은데 외부 전송이 꺼려지는 경우
- 자동완성, 로컬 파일 요약처럼 빠른 응답보다 프라이버시가 우선인 반복 작업

**아직 이른 경우:**
- 복잡한 리서치, 긴 문서 분석, 다단계 추론이 주요 용도인 경우
- 세팅에 시간 쓰기 싫고 그냥 결과만 빠르게 원하는 경우
- 8GB RAM 맥북으로 30B급 성능을 기대하는 경우

결국 "어떤 맥북으로, 어떤 일에 쓸 건지"에 달려 있어요.

## 앞으로 뭘 지켜봐야 할까

- **양자화 기술의 발전 속도**: Unsloth Dynamic 양자화처럼, 더 적은 메모리로 더 나은 성능을 내는 방식이 계속 나오고 있어요. 6~12개월 내 14B 모델이 현재 30B 수준의 성능에 도달할 가능성이 높아요.
- **Apple MLX 생태계**: 애플이 직접 밀고 있는 MLX 프레임워크가 Ollama와 경쟁하는 구도로 성숙하고 있어요. 네이티브 최적화 측면에서 주목할 만해요.
- **에이전트 응답 속도**: 이 리포트에서 Hermes의 7~12분 응답 시간이 병목이었어요. OpenClaw로 교체하면 1~3분으로 줄어드는 걸 확인했는데, 에이전트 프레임워크 경쟁이 로컬 실행의 실용성을 크게 바꿀 거예요.

지금 맥북이 16GB 이상이고 API 비용이 부담스럽다면, Ollama 설치하고 Gemma 3 12B 한 번 돌려보는 데 30분도 안 걸려요. 직접 써보는 게 가장 빠른 답이에요.
