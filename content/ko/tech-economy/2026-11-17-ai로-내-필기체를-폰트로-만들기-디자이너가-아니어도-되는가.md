노트에 휘갈겨 쓴 글씨가 설치형 폰트가 되는 데 1분도 안 걸린다면요?

2026년 현재, 타입 디자인은 더 이상 베지어 곡선을 다룰 줄 아는 사람만의 영역이 아니에요. AI 기반 폰트 생성 도구들이 빠르게 성숙하면서, 핸드폰 사진 한 장과 텍스트 설명 한 줄로 완성도 있는 폰트 파일을 뽑아내는 게 가능해졌거든요. 그런데 "AI가 다 해준다"는 말이 얼마나 사실인가요? 디자이너 없이 만든 폰트가 실제로 쓸 만한가요?

이 질문에 답하려면, 도구가 뭘 하는지와 사람이 여전히 뭘 해야 하는지를 정확히 나눠서 봐야 해요.

> **핵심 요약**
> - [YoFont](https://yofont.com/create-your-own-font)는 텍스트 설명, 참조 이미지, 손글씨 사진 세 가지 입력으로 1분 안에 TTF/OTF/WOFF/WOFF2 파일을 생성하며, 첫 폰트는 완전 무료예요.
> - [Kittl Flows](https://www.kittl.com/blogs/how-to-create-custom-fonts-with-ai-ais/)는 텍스트 프롬프트로 개별 글자를 생성해 조합하는 방식으로, 기존에 며칠 걸리던 작업을 1시간 안으로 줄였어요.
> - [draw-your-font](https://tilnote.io/en/pages/6af9adbe58258d5dd1bb5d51)처럼 오픈소스 도구는 AI를 "문자 인식" 단계에만 쓰고, 나머지는 결정론적 파이프라인으로 처리해요 — AI가 폰트 전체를 만드는 게 아니에요.
> - 상업적 사용을 고려한다면 라이선스, 출력 품질, 한국어 글리프 지원 여부를 반드시 사전에 확인해야 해요.

## 타입 디자인에 무슨 일이 일어나고 있나요

사실 손글씨를 폰트로 변환하는 개념 자체는 새로운 게 아니에요. Calligraphr 같은 도구는 오래전부터 사용자가 직접 글자를 그려서 업로드하면 폰트 파일로 변환해줬거든요. 문제는 그 "직접 그린다"는 과정이 꽤 번거로웠다는 거예요. 모든 글자를 일관된 스타일로 그려야 했고, 베이스라인 맞추는 것도 사람 손으로 해야 했어요.

변화가 본격화된 건 멀티모달 AI 모델이 이미지 입력을 처리할 수 있게 되면서부터예요. 2024년 말부터 지금까지, 이 분야의 변화는 세 방향으로 나뉘어요.

**첫째, 생성 방향.** AI가 아예 새로운 글자 형태를 만들어내는 방식이에요. Kittl Flows가 대표적이에요. "고딕 스타일의 대문자 H를 만들어줘" 같은 프롬프트로 개별 글자를 생성하고, 이걸 조합해서 완성된 알파벳을 구성해요. 기존 손글씨를 복제하는 게 아니라 새로운 타입페이스를 처음부터 만드는 거예요.

**둘째, 인식-변환 방향.** 실제 손글씨 사진을 찍고, AI가 거기서 문자를 인식한 뒤, 별도 파이프라인이 그걸 벡터로 변환해 폰트 파일을 만들어요. draw-your-font가 이 방식이에요. 여기서 AI의 역할은 사실 제한적이에요 — 어떤 글자인지 인식하는 것뿐이고, 나머지는 potrace 같은 결정론적 소프트웨어가 처리해요.

**셋째, 하이브리드 방향.** YoFont처럼 텍스트 프롬프트, 참조 이미지, 손글씨 사진 세 가지를 모두 받아서 60개 언어, 아홉 가지 문자 체계를 한 번에 처리하는 도구예요.

그래서 지금 이게 중요한 이유가 있어요. 브랜드 아이덴티티 비용은 중소 규모 팀에게 여전히 부담스러운 항목이에요. 고유한 타입페이스 커미션 비용은 수백만 원에서 시작하는 경우가 많거든요. AI 도구들이 그 진입 장벽을 실질적으로 낮추고 있어요.

## 세 가지 도구, 세 가지 접근 방식

### 프롬프트로 타입페이스 만들기: Kittl Flows

[Kittl 블로그에 따르면](https://www.kittl.com/blogs/how-to-create-custom-fonts-with-ai-ais/) 이 도구의 핵심은 7단계 워크플로우예요.

Smart Board 프로젝트에서 글자를 하나씩 프롬프트로 생성하고, 대소문자와 숫자, 구두점까지 같은 스타일로 완성한 뒤, 투명 배경 이미지로 내보내요. 그걸 Calligrapher라는 무료 폰트 빌딩 도구에 업로드하면 TTF 파일이 완성돼요.

Kittl 측에서는 이 과정을 1시간 안에 완료했다고 밝혔어요. 기존에 며칠씩 걸리던 작업이에요. 개별 글자를 선택적으로 재생성할 수 있다는 것도 실용적인 장점이에요. 전체를 다시 만들 필요 없이 맘에 안 드는 글자만 골라서 바꿀 수 있거든요.

### 손글씨 사진 → 폰트 파일: YoFont

[YoFont](https://yofont.com/create-your-own-font)의 접근은 조금 달라요. 텍스트 설명, 참조 이미지, 손글씨 사진 중 하나를 입력하면 1분 안에 TTF, OTF, WOFF, WOFF2 파일과 CDN 호스팅 URL까지 나와요.

기술 스펙을 보면 한 번의 생성으로 60개 언어와 아홉 가지 문자 체계를 커버해요. Thin, Regular, Bold 세 가지 굵기도 자동 생성되고요. 각 글리프는 브라우저 내 Studio에서 편집도 가능해요.

실제 성능 데이터로는 다섯 단어, 열세 단어짜리 짧은 문장에서 각각 94개 글리프를 커버하는 폰트를 생성했다는 사례가 공개돼 있어요.

첫 폰트는 완전 무료이고, 이후에는 글리프당 구매나 구독 플랜이 필요해요. 상업적 사용에는 별도 라이선스가 필요하고요.

### AI를 도구로만 쓰는 오픈소스: draw-your-font

[TILNOTE의 분석](https://tilnote.io/en/pages/6af9adbe58258d5dd1bb5d51)이 이 도구를 다루는 방식이 흥미로워요. draw-your-font는 MIT 라이선스 오픈소스 도구인데, AI의 역할이 명확하게 제한돼 있어요.

파이프라인을 보면: 사진 이진화 → 문자 영역 분리 → 문자 레이블링 → potrace를 통한 벡터화 → 베이스라인 정렬 → 폰트 생성. AI(Claude Vision)는 세 번째 단계, 즉 문자 인식에만 개입해요. 벡터 변환은 AI 없이 처리돼요.

많은 도구들이 "AI가 다 해준다"는 인상을 주지만, 실제로는 AI 역할이 파이프라인의 일부에 불과한 경우가 많아요. draw-your-font는 그걸 명확하게 보여줘요.

한국어 지원은 별도 검증이 필요하고, 출력 품질이 상업 배포 수준을 보장하지 않는다는 점도 명시돼 있어요.

### 도구 비교: 무엇이 나에게 맞을까

| 항목 | Kittl Flows | YoFont | draw-your-font |
|------|-------------|--------|----------------|
| 입력 방식 | 텍스트 프롬프트 | 텍스트/이미지/손글씨 | 손글씨 사진 |
| 한국어 지원 | 프롬프트로 가능 | 60개 언어 명시 | 별도 검증 필요 |
| 출력 형식 | TTF (Calligrapher 경유) | TTF/OTF/WOFF/WOFF2 | TTF/WOFF/WOFF2 |
| 무료 플랜 | Kittl 계정 필요 | 첫 폰트 무료 | 완전 무료 (오픈소스) |
| 상업 라이선스 | Kittl 플랜 따름 | 별도 구매 필요 | MIT (소프트웨어만) |
| 편집 가능성 | 글자 단위 재생성 | 글리프 단위 편집 | 두께/스무딩 조정 |
| 적합한 사용자 | 디자이너, 크리에이터 | 멀티언어 웹폰트 필요 | 개발자, DIY 유저 |

손글씨를 그대로 살리고 싶다면 YoFont나 draw-your-font가 맞고, 아예 새로운 스타일을 만들고 싶다면 Kittl Flows가 나아요. 비용 없이 직접 제어하고 싶다면 draw-your-font가 현실적인 선택이에요.

## 실제로 쓸 때 무엇을 조심해야 할까요

**용도별로 접근 방식이 달라요.**

개인 프로젝트나 소규모 굿즈 제작이라면 YoFont의 무료 플랜이나 draw-your-font로 충분히 시작할 수 있어요. 첫 폰트를 무료로 내보내고 실제 텍스트에 얹어보는 것만으로도 쓸 수 있는지 아닌지 금방 판단 가능해요.

상업적 사용이라면 반드시 세 가지를 먼저 확인해야 해요:

- **라이선스 범위**: YoFont는 로고, 패키징, 유료 클라이언트 작업에 상업 라이선스가 필요해요. draw-your-font의 MIT 라이선스는 소프트웨어에만 해당하고, Claude API 사용 비용과 출력 폰트의 배포 권리는 별개예요.
- **한국어 글리프**: 한국어 콘텐츠에 쓸 거라면 실제 한글 텍스트로 미리 테스트가 필수예요. YoFont는 60개 언어를 명시하지만, draw-your-font는 한국어 지원을 별도 검증이 필요하다고 직접 밝히고 있어요.
- **실제 콘텐츠 미리보기**: 샘플 미리보기에서 멀쩡해 보여도 실제 쓸 텍스트에 없는 글자가 빠져 있는 경우가 있어요. 배포 전에 실제 사용할 텍스트로 테스트하는 과정은 건너뛰면 안 돼요.

TILNOTE의 분석이 제시하는 평가 기준이 여기서 유용해요. "AI가 얼마나 자동화하는가"보다 "어디서 인식이 일어나고, 어디서 결정론적 처리가 일어나고, 사람이 검토해야 하는 부분이 어디인가"를 보는 거예요. draw-your-font 기준으로는 벡터화 전 레이블 검증과 실제 콘텐츠 미리보기 테스트, 두 단계가 반드시 사람 손을 거쳐야 해요.

## 앞으로 어떻게 될까요

정리하면 이렇게 볼 수 있어요:

- AI 폰트 생성 도구는 세 갈래 — 프롬프트 생성형, 손글씨 변환형, 하이브리드 — 로 나뉘고, 각각 목적이 달라요.
- "AI가 다 한다"는 말은 절반은 맞고 절반은 과장이에요. AI 역할이 파이프라인의 일부에만 적용되는 경우가 많아요.
- 무료 시작 → 빠른 테스트 → 상업 라이선스 확인, 이 순서가 현실적인 도입 경로예요.
- 한국어 지원 여부는 가정하면 안 되고, 직접 테스트해야 해요.

앞으로 6~12개월을 보면, 멀티언어 지원과 웹폰트 직접 배포 연동이 주요 경쟁 포인트가 될 것 같아요. 현재 YoFont가 CDN 호스팅 URL을 바로 제공한다는 점도 그 흐름이에요. 오픈소스 쪽에서는 한국어 같은 복잡한 문자 체계 지원이 얼마나 성숙해지느냐가 관건이고요.

한 가지만 기억하자면 이거예요. 도구가 아무리 좋아도, 폰트가 실제로 쓰이는 맥락에서 테스트하는 과정은 사람 몫이에요. AI가 글자를 만들어준다고 해서 그게 바로 "내 폰트"로 쓸 수 있다는 뜻은 아니에요.

여러분이 만들 폰트는 어떤 텍스트에 얹힐 예정인가요? 그 텍스트로 먼저 테스트해 봤을 때 어떤 결과가 나오는지 — 거기서 진짜 판단이 시작돼요.
