2026년 5월 15일, Vercel Labs가 조용히 공개한 언어 하나가 깃허브에서 24시간 만에 별 900개를 넘겼어요. 이름은 **Zero** (`.0` 확장자). 그런데 흥미로운 건 이 언어가 사람이 읽기 편하도록 설계된 게 아니라는 거예요. 컴파일러 출력이 기본적으로 JSON이고, 에러 메시지는 AI 에이전트가 자동으로 파싱하고 수정할 수 있게 만들어졌어요. 개발자가 아니어도 이걸 알아야 할까요 — 이 질문을 이 글에서 풀어볼게요.

> **핵심 요약**
> - Vercel Labs는 2026년 5월 15일 Zero v0.1.2를 Apache-2.0 라이선스로 공개했으며, 출시 24시간 만에 깃허브 별 900개를 돌파했다.
> - Zero의 컴파일러는 기본 출력이 구조화된 JSON으로, 안정적인 에러 코드(예: `NAM003`)와 수정 방법 ID를 포함해 AI 에이전트가 에러를 자동 처리할 수 있도록 설계됐다.
> - 기존 언어(Rust, TypeScript, Go)는 에이전트 친화적 기능을 일부 갖추지만, Zero는 처음부터 에이전트를 1순위 사용자로 설계한 최초의 시스템 프로그래밍 언어다.
> - OpenAI Codex가 주간 활성 사용자 400만 명을 돌파한 시점에 나온 이 흐름은, 코드를 쓰는 주체가 사람에서 에이전트로 이동하고 있다는 신호다.
> - Zero는 현재 실험적 상태(비프로덕션)지만, 그 설계 철학은 기존 언어 생태계 전반에 영향을 줄 가능성이 높다.

## 왜 지금 이게 나왔을까 — 배경과 맥락

2026년 상반기, 코드를 쓰는 건 더 이상 사람만의 일이 아니에요.

theunwindai.com의 보도에 따르면, 투자자 Peter Steinberger는 한 달에 API 토큰으로만 130만 달러(약 18억 원)를 소비했어요. 하루 평균 2만 달러. 대부분 GPT-5.5 기반 자율 저장소 관리 에이전트를 운영하는 데 쓴 거예요. 극단적인 사례처럼 보이지만, OpenAI Codex가 주간 활성 사용자 400만 명을 돌파했다는 데이터는 이게 더 이상 예외가 아니라는 걸 보여줘요.

문제는 에이전트가 코드를 쓰고 실행하는 환경이 여전히 사람을 위해 설계됐다는 거예요. 기존 언어들의 에러 메시지는 터미널 텍스트로 출력되고, 에이전트는 이걸 매번 자연어 파싱으로 해석해야 해요. 컴파일러 버전이 바뀌면 에러 문구도 달라지고, 에이전트가 만들어둔 "수정 플레이북"이 통째로 깨지기도 하죠.

Vercel은 이 지점을 정확히 겨냥했어요. Next.js와 AI SDK를 운영하면서 에이전트 기반 개발의 마찰 지점을 직접 목격한 거예요. Agentic Infrastructure를 정식 카테고리로 내세우기 시작한 것도 같은 흐름이에요.

## Zero가 실제로 뭘 바꾸려는 건지 — 핵심 분석

### 에이전트가 직접 읽는 컴파일러 에러

aiautomationglobal.com의 기술 분석에 따르면, Zero 컴파일러의 기본 출력은 JSON이에요. 사람이 읽기 불편한 게 맞아요. 의도적으로 그렇게 만든 거예요.

에러 코드는 `NAM003` 같은 형태로 고정돼 있고, 컴파일러 버전이 바뀌어도 이 코드는 유지돼요. 에이전트 입장에서는 "이 에러가 나오면 이렇게 수정한다"는 플레이북을 한 번 만들면 계속 쓸 수 있는 거예요. 수정 방법 ID도 열거형으로 정의돼 있어요 — `declare-missing-symbol`, `add-capability` 같은 식으로요.

`zero skills` 엔드포인트도 있어요. 현재 사용 중인 컴파일러 버전에 맞는 문서를 에이전트가 직접 가져올 수 있게 해주는 기능이에요. 에이전트가 구버전 문서를 참고해서 잘못된 코드를 짜는 문제를 막는 거예요.

### Capability 기반 I/O — 함수 서명만 보면 동작을 다 알 수 있다

Zero에서 파일 읽기, 네트워크 요청, 환경변수 접근 같은 모든 부수효과(side effect)는 `World` 파라미터를 명시적으로 통과해야 해요.

쉽게 말하면, 함수 서명만 봐도 이 함수가 뭘 하는지 전부 알 수 있어요. 에이전트 입장에서는 코드 전체를 실행해보지 않아도 동작을 예측할 수 있다는 뜻이에요. 기존 언어에서 에이전트가 코드를 잘못 생성하는 주요 원인 중 하나가 숨겨진 전역 상태나 암묵적 비동기 처리였는데, Zero는 이걸 설계 차원에서 없애버렸어요.

바이너리 크기는 10 KiB 이하, 가비지 컬렉터 없음, 이벤트 루프 오버헤드 없음 — 에이전트가 빠르게 실행하고 결과를 받아야 하는 환경에 맞게 최소화했어요.

### 기존 언어와 비교하면

| 기준 | Zero | Rust | TypeScript | Go |
|------|------|------|------------|-----|
| 기본 에러 출력 | JSON (구조화) | 텍스트 (`--error-format=json` 옵션) | 텍스트 | 텍스트 |
| 안정적 에러 코드 | ✅ 버전 불변 | ❌ | ✅ (수정 ID 없음) | ❌ |
| 타입별 수정 ID | ✅ | ❌ | ❌ | ❌ |
| Capability 기반 I/O | ✅ 필수 | ❌ | ❌ | ❌ |
| 에이전트 1순위 설계 | ✅ | ❌ (사람 중심) | ❌ (사람 중심) | ❌ (사람 중심) |
| 프로덕션 준비 | ❌ 실험적 | ✅ | ✅ | ✅ |

Rust는 옵션으로 JSON 에러를 켤 수 있고, TypeScript는 안정적인 에러 코드를 갖고 있어요. 하지만 두 언어 모두 에이전트를 위해 처음부터 설계된 건 아니에요. 기능이 나중에 추가된 거죠. Zero는 반대로 에이전트가 1순위 사용자이고, 사람이 쓰기 불편한 건 감수한 설계예요.

## 개발자가 아니어도 이걸 알아야 하는 이유

**제품 기획자/PM 관점**

에이전트가 코드를 자동으로 쓰고 수정하는 환경이 확산되면, 제품 개발 속도 자체가 달라져요. 지금은 개발자가 에러를 보고 고치는 루프에 시간이 걸리지만, 에이전트가 에러를 JSON으로 받고 자동 수정하는 루프가 안정화되면 그 속도가 비교할 수 없이 빨라져요. 어떤 기능에 에이전트를 붙일 수 있는지 생각하기 시작해야 할 시점이에요.

**개발자 관점**

당장 Zero를 쓸 필요는 없어요. 실험적 상태고 프로덕션엔 맞지 않아요. 하지만 Zero의 설계 철학 — 구조화된 에러, Capability 기반 I/O — 은 기존 언어에도 점진적으로 적용될 가능성이 높아요. TypeScript나 Rust에서 에이전트 친화적 패턴을 미리 써보는 게 준비가 될 수 있어요.

**투자자/비즈니스 관점**

비즈니스적 답은 간단해요. "에이전트 인프라가 다음 플랫폼 전쟁의 무대"라는 거예요. Vercel이 언어 레이어까지 내려간 건 단순한 실험이 아니에요. 에이전트가 코드를 쓰는 환경 전체를 장악하려는 포지셔닝이에요.

**주시할 신호들**:
- Zero가 v0.2 이상으로 올라가며 기능이 안정화되는 시점
- TypeScript나 Rust 공식 로드맵에 에이전트 친화적 에러 포맷이 포함되는지
- Vercel 경쟁사(AWS, Cloudflare)가 유사한 에이전트 인프라를 발표하는지

## 앞으로 어떻게 될까

**핵심 요약**:
- Zero는 2026년 5월 출시, 에이전트가 에러를 파싱하고 자동 수정할 수 있는 최초의 에이전트-퍼스트 시스템 언어
- 기존 언어 대비 구조화된 JSON 출력, 안정적 에러 코드, Capability 기반 I/O가 핵심 차별점
- 현재 실험적 상태지만, 그 설계는 기존 언어 생태계에 영향을 줄 기준점이 될 수 있음

앞으로 6~12개월 안에 볼 수 있는 변화:
- **단기**: Rust, Go 커뮤니티에서 Zero의 에이전트 친화적 에러 포맷을 채택하는 논의가 시작될 가능성이 있어요
- **중기**: Vercel이 Zero를 자사 AI SDK 및 에이전트 인프라와 통합하면, 에이전트 기반 개발 파이프라인의 표준이 될 수 있어요

결국 이 질문이 남아요. 에이전트가 코드를 쓰는 세상에서, 프로그래밍 언어의 첫 번째 사용자는 누구여야 할까요? Vercel의 답은 명확했어요. 그리고 이 답이 맞다면, 나머지 언어 생태계는 곧 따라가야 할 거예요.
