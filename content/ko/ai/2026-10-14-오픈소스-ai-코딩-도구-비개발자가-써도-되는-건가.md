"코딩 몰라도 AI가 다 해준다"는 말, 반은 맞고 반은 틀렸어요.

2026년 현재, Cursor·GitHub Copilot 같은 유료 도구는 이미 대중화됐고, 오픈소스 AI 코딩 도구 시장도 빠르게 무르익고 있어요. OpenCode 하나만 봐도 75개 이상의 LLM 제공자를 지원하고, 무료 로컬 모델부터 저가 클라우드 API까지 선택지가 넓어졌죠. 그런데 정작 중요한 질문은 따로 있어요. **오픈소스 AI 코딩 도구, 비개발자가 써도 되는 건가.** 정말로요.

> **핵심 요약**
> - DeepSeek V3.2 기준 토큰 비용은 Claude Sonnet 대비 약 50배 저렴하지만, 비개발자의 실제 진입 장벽은 비용이 아니라 "어디가 잘못됐는지 모른다"는 점이에요.
> - 오픈소스 로컬 모델(Ollama 기반)은 16GB RAM부터 의미 있는 수준의 코딩 성능을 제공하며, 완전 무료로 운영 가능해요.
> - 바이브 코딩(Vibe Coding)으로 비개발자도 게임을 만들 수 있지만, 버그 하나에 6시간이 넘는 디버깅 병목은 피할 수 없어요.
> - Codex Desktop 같은 도구는 비개발자를 "프롬프트 전문가"가 아닌 "구조 설계자"로 위치시키며, 이 차이가 실제 사용 결과를 가르는 핵심이에요.
> - 지금 단계에서 비개발자에게 오픈소스 AI 코딩 도구는 "쓸 수 있다"와 "생산적으로 쓸 수 있다" 사이에 분명한 간극이 존재해요.

## 비용 구조가 완전히 바뀌었어요

1년 전만 해도 AI 코딩 도구의 가장 큰 진입 장벽은 가격이었어요. Claude Sonnet 계열을 한 달 제대로 쓰면 100달러 금방 넘거든요. 병렬 에이전트 환경에서는 월 200달러도 쉽게 나와요.

지금 오픈소스·저가 모델의 가격 차이는 이 정도예요.

| 모델 | 입력 (1M 토큰) | 출력 (1M 토큰) | 특징 |
|------|---------------|---------------|------|
| Claude Sonnet 4.5 | $3.00 | $15.00 | 고성능 기준선 |
| DeepSeek V3.2 | $0.28 | $0.42 | 성능 대비 최저가 |
| MiniMax M2.1 | $0.30 | $1.20 | 중간 선택지 |
| GLM-4.7 | $0.60 | $2.20 | GLM 코딩 플랜 월 $3 |
| Ollama (로컬) | $0 | $0 | 완전 무료, 영구적 |

DeepSeek V3.2은 Claude Sonnet 대비 50배 가까이 싸요. Claude에 월 100달러 쓰던 걸 DeepSeek으로 바꾸면 2~3달러면 비슷한 작업량이 돼요. 비용 장벽은 사실상 사라진 거예요.

그래서 비개발자도 뛰어들고 있어요. 마케터, 기획자, 운영팀 사람들이 Cursor를 열거나 바이브 코딩을 시도하기 시작했죠. 오픈소스 AI 코딩 도구를 써야 하나라는 질문은 이제 단순한 호기심이 아니라 실무 고민이 됐어요.

## 실제로 해봤을 때 어떤 일이 생기나

### 초반 30분: 생각보다 잘 돼요

코딩 지식 없이 체스 게임, 드래곤 플라이트 스타일 게임, 3매치 퍼즐 게임을 AI로 만들어낸 사례가 있어요. 자연어로 원하는 걸 설명하면 AI가 코드를 뽑아내고, 수정 요청을 반복하는 방식이에요. 프로토타입 단계에서는 접근성이 꽤 좋아요.

간단한 파일 이름 바꾸기, CSV 정리, 이미지 리스트 생성 같은 소규모 스크립트도 코딩 지식 없이 뽑아낼 수 있고요.

### 그 다음부터가 문제예요

기능이 쌓이기 시작하면 상황이 달라져요. 버그 하나를 잡는 데 6시간이 걸렸다는 후기도 있어요. 디버깅 시간이 길어질수록 토큰 소모도 늘고, 비용도 올라가요. 그런데 진짜 문제는 따로 있어요.

**"어디가 잘못됐는지 모른다."**

코드 리터러시가 없으면 AI가 틀린 방향으로 달려가도 알아채기가 어려워요. 진단 자체를 AI에 완전히 의존하게 되는 구조죠. Unity 기반 UI처럼 복잡한 환경에서는 렌더링이 깨지거나 요소가 사라져도 왜 그런지를 파악하는 게 거의 불가능해요.

### 로컬 모델은 또 다른 얘기예요

Ollama로 로컬 모델을 돌리려면 하드웨어 조건이 있어요.

- **8GB RAM**: Qwen2.5-Coder 1.5B~3B — 간단한 작업 가능
- **16GB RAM**: Qwen2.5-Coder 7B — HumanEval 점수 84~88%, 33B급 모델과 비슷한 성능
- **48~64GB RAM**: Qwen3-Coder 30B — 상위급 코딩 성능

16GB RAM 노트북이 있다면 Qwen2.5-Coder 7B 정도는 돌아가요. 클라우드 비용 없이 완전 오프라인으로 쓸 수 있다는 건 분명한 장점이에요. 보안 정책이 엄격한 환경에서는 결정적인 이유가 되기도 하죠.

다만 설정 과정이 쉽지 않아요. Ollama는 `opencode.json`에서 수동으로 커스텀 엔드포인트를 추가해야 해요. 명령줄 인터페이스(CLI)를 한 번도 안 써본 사람한테는 첫 관문부터 막혀요.

## 비개발자가 잘 쓰는 경우 vs 막히는 경우

AI 코딩 도구를 잘 쓰는 비개발자의 공통점이 있어요. "프롬프트를 잘 쓰는 사람"이 아니라 **"일을 어떻게 나눌지 아는 사람"**이에요.

프로젝트(어느 폴더에서 작업할지), 스레드(지금 이 작업만 집중), 리뷰(지시 → 실행 → 확인) — 이 세 가지 구조를 먼저 잡으면 결과물 품질이 달라지거든요. 마케터나 운영 기획자가 이미 일상적으로 하는 업무 분류 방식이에요.

**잘 쓰이는 경우:**
- 파일 정리, CSV 변환, 반복 작업 자동화
- 웹 UI 초안 생성 및 반복 수정
- 단일 기능 프로토타입 제작

**자주 막히는 경우:**
- 기능 여러 개가 연결된 복잡한 앱
- 오류 메시지를 해석해야 하는 디버깅 상황
- 로컬 모델 초기 설정 (CLI, JSON 설정 파일)
- 생성된 코드가 의도대로 작동하는지 검증

## 그래서 지금 어떻게 접근하면 현실적인가

**1단계 — 클라우드 저가 모델부터:** DeepSeek V3.2나 GLM-4.7 같은 저가 API를 먼저 써보세요. GLM 코딩 플랜은 월 3달러에 5시간 윈도우당 120개 프롬프트를 쓸 수 있어요. 설정이 간단하고 비용 부담이 없어요.

**2단계 — 작업 구조 설계 먼저:** 프롬프트 잘 쓰는 법보다 "이 일을 어떻게 나눌까"를 먼저 생각하세요. 프로젝트 폴더를 `01_Research`, `02_Drafts`, `03_Assets`로 나누는 것만으로도 AI 도구의 출력 품질이 달라져요.

**3단계 — 로컬 모델은 나중에:** Ollama + Qwen2.5-Coder 7B 조합은 16GB RAM이 있다면 도전할 만해요. 다만 CLI에 익숙해진 다음에 시도하는 게 맞아요. 처음부터 로컬 모델 세팅을 하면 설정 문제에서 지쳐요.

참고로, 지금 Groq 무료 티어는 하루 14,400 요청이 가능하지만 Google Gemini 2.5 Pro는 하루 25 RPD로 줄었어요. 무료 티어 정책은 계속 바뀌고 있어요. 반면 모델 성능은 빠르게 올라가고 있어요. Qwen2.5-Coder 7B이 이미 HumanEval 84~88%를 찍는다는 건, 2년 전 33B짜리 모델 성능을 16GB 노트북에서 무료로 돌린다는 뜻이에요. 이 속도라면 1년 안에 비개발자의 진입 장벽은 지금보다 의미 있게 낮아질 거예요.

## "쓸 수 있다"와 "쓸 만하다" 사이

오픈소스 AI 코딩 도구, 비개발자가 써도 되는 건가. 현실적인 답은 이래요.

- **단순 자동화, 파일 처리, 프로토타입**: 지금 당장 써도 돼요.
- **복잡한 기능 개발, 디버깅, 로컬 모델 세팅**: 기초 코드 리터러시 없이는 벽에 부딪혀요.
- **비용 장벽**: 사실상 사라졌어요. DeepSeek V3.2로 월 몇 달러면 충분해요.
- **진짜 장벽**: 비용이 아니라 "뭐가 잘못됐는지 모르는 상태"예요.

지금 당장 뭔가 해보고 싶다면, GLM 코딩 플랜 3달러로 시작해서 작업 구조 나누는 연습부터 하세요. 그게 프롬프트 잘 쓰는 것보다 결과를 훨씬 빠르게 바꿔줄 거예요.

그리고 한 가지만 생각해보세요. 코딩 없이 AI를 쓰는 사람과, 기초 코드 리터러시를 갖추고 AI를 쓰는 사람 — 1년 후 둘의 생산성 차이는 얼마나 벌어질까요?
