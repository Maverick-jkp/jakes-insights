ChatGPT 프롬프트 창에 고객 이름, 계약 금액, 내부 메모를 통째로 붙여넣은 적 있으세요? 2026년 현재, 직장인 열 명 중 여섯 명이 AI 도구를 업무에 쓰는데, 개인정보·기업 기밀 유출 위험을 인지한 비율은 절반도 안 돼요.

규제 환경도 바뀌고 있어요. 개인정보보호위원회(PIPC)가 2026년 생성형 AI 사용 가이드라인을 업데이트했고, 미국 FTC도 기업 AI 사용 모니터링을 강화하는 중이에요.

이 글에서 다룰 내용은 이렇습니다:

- 어떤 정보가 AI에 들어가면 안 되는지 (카테고리별)
- AI 서비스마다 데이터 처리 방식이 얼마나 다른지
- 직장인이 당장 쓸 수 있는 익명화 기술
- 회사 차원에서 필요한 최소한의 대응

---

> **핵심 요약**
> - ChatGPT 등 생성형 AI에 입력한 프롬프트는 모두 서버로 전송된다. 로컬에서 처리되지 않는다.
> - 개인정보보호위원회는 주민등록번호, 금융 인증 정보, 제3자 개인정보를 AI에 직접 입력하지 말 것을 명시적으로 권고하고 있다.
> - NIST는 이름·생년월일·직장명처럼 무해해 보이는 데이터도 여러 대화에 걸쳐 조합되면 개인 식별이 가능해지는 '집계 위험(Aggregation Risk)'을 경고한다.
> - 실수로 민감 정보를 입력했을 때 대화 삭제만으로는 부족하다. API 키·비밀번호는 즉시 폐기하고 재발급해야 한다.

## AI 도구, 데이터를 어떻게 처리하나요?

먼저 작동 방식부터 봐야 해요.

ChatGPT나 Claude 같은 생성형 AI에 입력하는 모든 프롬프트와 첨부 파일은 로컬에서 처리되지 않아요. 전부 서비스 제공사 서버로 전송돼요. 그것도 즉시.

서비스마다 차이는 있어요. 대화 기록을 얼마나 보관하는지, 모델 학습에 쓰는지, 직원이 직접 검토하는지 — 이게 다 달라요. 개인 계정이냐 기업 계정이냐에 따라서도 정책이 갈려요.

PIPC 가이드라인이 권고하는 첫 번째 행동은 명확해요. AI 서비스를 쓰기 전에 그 서비스의 데이터 보관 기간, 학습 사용 여부, 대화 삭제 가능 여부를 직접 확인하세요. 귀찮더라도요.

쉽게 기억할 기준이 하나 있어요. "이 정보가 인터넷에 공개돼도 괜찮은가?" — 답이 '아니오'라면 넣지 마세요.

## 절대 넣으면 안 되는 7가지 카테고리

PIPC와 FTC 가이드라인을 종합하면 금지 항목은 크게 7가지예요.

**1. 고유 식별자**
주민등록번호, 여권 번호, 운전면허 번호. 이것 하나면 신원 도용, 금융 범죄, 계정 탈취까지 연결될 수 있어요.

**2. 비밀번호·인증 코드**
OTP, 문자 인증 코드, API 키, 복구 코드. AI는 로그인 문제를 해결할 때 실제 비밀번호가 필요하지 않아요. 절대로.

**3. 금융 정보**
카드 번호, CVC, 계좌 비밀번호. 카드 번호 + 이름 + 생년월일 조합은 위험 수위가 급격히 올라가요.

**4. 사내 기밀 문서**
FTC는 내부 문서나 고객 데이터를 AI에 넣는 것 자체가 기밀 노출이라고 경고해요. 체크 포인트는 이거예요: "이 정보를 외부에 공유할 권한이 나에게 있나?"

**5. 제3자 개인정보**
동료, 고객, 환자 정보를 그들 동의 없이 AI에 넣는 것 — PIPC가 명시적으로 금지해요.

**6. 건강·의료 기록**
"LDL 160mg/dL" 같은 수치만 넣으면 돼요. 이름과 환자 번호가 붙은 전체 검사 결과지는 넣을 이유가 없어요.

**7. 정밀 위치 정보**
정확한 집 주소 + 이름 + 전화번호 + 일과 패턴 — 이게 합쳐지면 한 사람을 완전히 특정할 수 있어요.

## 계정 유형별 비교: 개인 vs 기업 AI 계정

가장 많이 놓치는 부분이 여기예요. 같은 AI 도구도 계정 유형에 따라 데이터 처리 방식이 달라요.

| 비교 항목 | 개인 무료 계정 | 개인 유료 계정 | 기업용 엔터프라이즈 계정 |
|-----------|--------------|--------------|----------------------|
| 대화 학습 사용 | 기본값 허용 | 설정으로 거부 가능 | 대부분 비활성화 |
| 데이터 보관 기간 | 서비스 정책에 따름 | 단축 가능 | 계약으로 명시 |
| 직원 검토 가능성 | 있음 | 낮음 | 계약 조건에 따름 |
| 대화 삭제 효과 | 즉시 미반영 가능 | 정책 확인 필요 | 계약상 보장 가능 |
| 파일 업로드 보관 | 임시 보관 | 임시 보관 | 별도 정책 적용 |
| **추천 대상** | 개인 학습·창작 | 민감도 낮은 업무 | 기업 업무·고객 데이터 |

엔터프라이즈 계정도 조직 보안 정책이 개인 계정과 별도로 적용돼요. 같은 ChatGPT라도 회사에서 제공한 계정이라면 사내 정책을 먼저 확인해야 해요.

가장 위험한 조합은 이거예요. 회사 업무에 개인 무료 계정을 쓰는 것. 고객 데이터가 모델 학습에 쓰일 수 있고, 삭제 요청도 즉시 반영되지 않을 수 있어요.

## 당장 쓸 수 있는 익명화 기술 3가지

이론은 알겠는데 실제로 어떻게 하냐고요? 간단해요.

**1. 이름 치환**
실명 대신 알파벳이나 레이블로 교체하세요. 김민지 → A, B사 → 협력사. AI가 필요한 건 이름이 아니라 맥락이에요.

**2. 수치 범위화**
정확한 숫자 대신 범위로. "매출 23억 4천만 원" → "20억~25억 수준". 계약 금액, 급여, 내부 지표 모두 같은 방식으로 적용할 수 있어요.

**3. 코드 내 시크릿 마스킹**
개발자라면 특히 중요해요. `API_KEY = "sk-real-key"` 같은 하드코딩된 값은 붙여넣기 전에 `API_KEY = "[REDACTED]"`로 교체하세요. PIPC가 명시적으로 권고하는 방법이에요.

참고로, PDF나 엑셀 파일에 숨겨진 메타데이터도 확인하세요. 작성자, 날짜, 회사 정보가 파일 속성에 묻어있을 수 있거든요.

## 실수했다면? 지금 당장 할 것

입력하면 안 되는 걸 이미 넣었다면 어떻게 해야 할까요?

대화 삭제는 첫 번째 단계예요. 하지만 충분하지 않아요. API 키나 비밀번호를 실수로 넣었다면 해당 자격증명을 즉시 폐기하고 새 것으로 교체해야 해요. 삭제 ≠ 보안 복구예요.

그리고 "대화 삭제"와 "향후 저장 중단"은 별개 기능이에요. 설정에서 둘 다 확인해야 해요.

## 회사는 무엇을 준비해야 하나

개인 직원의 주의만으로는 한계가 있어요. NIST AI 위험 관리 프레임워크와 PIPC 권고에 따르면 기업 차원의 최소 대응은 이렇게 돼요:

- **승인된 AI 서비스 목록** 운영 (어떤 도구를 써도 되는지)
- **금지 입력 카테고리 명시** (고객 데이터, 계약서 원본 등)
- **파일 업로드 제한 정책** 수립
- **출력물 검토 담당자** 지정

DLP(데이터 유출 방지) 솔루션이 없어도 이 네 가지는 할 수 있어요. 핵심 원칙은 AI 접근 자체를 막는 게 아니라, AI에 들어가는 것을 관리하는 거예요.

## 앞으로 6-12개월, 뭘 봐야 하나

**정리하면:**

- AI 입력 데이터는 전부 서버로 간다. 로컬 처리 아니에요.
- 7개 카테고리 — 주민번호, 비밀번호, 금융 정보, 사내 기밀, 제3자 정보, 의료 기록, 위치 정보 — 는 직접 입력 금지
- 개인 무료 계정 + 업무 데이터 조합이 가장 위험해요
- 익명화는 어렵지 않아요. 이름 치환 + 수치 범위화 + 코드 마스킹, 세 가지면 돼요

앞으로 주시할 신호는 세 가지예요.

첫째, EU AI Act 세부 시행 규칙이 2027년 초까지 순차 적용되면서 한국 기업의 대유럽 서비스에도 영향이 생길 거예요. 둘째, 주요 AI 서비스들이 엔터프라이즈 계정 데이터 보호 정책을 강화하는 추세예요 — 계약 조건을 다시 읽어볼 타이밍이에요. 셋째, PIPC의 2026년 가이드라인은 계속 업데이트되고 있어요. 반기별로 한 번씩 확인하는 게 좋아요.

마지막으로 하나만요. 지금 쓰는 AI 도구의 데이터 정책 페이지, 마지막으로 읽은 게 언제예요? 어쩌면 생각보다 많은 것들이 바뀌어 있을 거예요.
