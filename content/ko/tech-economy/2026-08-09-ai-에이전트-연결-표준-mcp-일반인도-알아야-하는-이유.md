AI가 "말"만 하던 시대는 끝났어요. 이제 AI는 직접 실행해요. 캘린더에 일정을 잡고, 코드를 배포하고, 데이터베이스를 수정하죠. 그 실행을 가능하게 하는 연결 고리가 바로 **AI 에이전트 연결 표준 MCP**예요.

2024년 11월 Anthropic이 조용히 공개한 MCP(Model Context Protocol)는 처음엔 개발자들 사이에서도 큰 관심을 못 받았어요. 그런데 2025년 3월, OpenAI가 ChatGPT에 MCP를 통합한다고 발표하면서 판이 뒤집혔죠. 그로부터 1년 남짓 지난 지금, Anthropic·OpenAI·Google·Microsoft·Amazon이 모두 이 표준을 채택했어요. Python/TypeScript SDK의 월간 다운로드는 9,700만 건을 넘겼고요. 이게 왜 일반인에게도 중요한 이야기인지, 지금부터 짚어볼게요.

> **핵심 요약**
> - MCP는 AI 모델과 외부 도구를 연결하는 표준 프로토콜로, 2024년 11월 Anthropic이 공개했고 현재 업계 전반에 걸쳐 사실상 표준(de facto standard)이 됐어요.
> - OpenAI·Google·Microsoft 등 주요 AI 기업이 모두 채택했으며, MCP SDK 월간 다운로드는 9,700만 건을 초과해요.
> - 기존에는 AI 앱 M개가 도구 N개에 연결하려면 M×N개의 개별 코드가 필요했지만, MCP는 이를 M+N으로 줄여요.
> - 2025년 12월 Linux Foundation 산하 Agentic AI Foundation(AAIF)으로 거버넌스가 이전되며 장기 오픈 표준으로 자리잡았어요.
> - 일반 사용자에게는 "AI가 내 앱을 대신 조작하는 시대"를 여는 기반 기술이라는 점에서 직접적 영향이 있어요.

## MCP가 등장하기 전, 뭐가 문제였을까요?

AI 모델에 외부 도구를 연결하는 건 생각보다 훨씬 번거로운 일이에요. 예를 들어 Claude가 Slack, Google Drive, GitHub, Notion 네 개 서비스를 동시에 쓰려면, 각 서비스마다 별도의 연동 코드를 만들어야 했어요. 개발사 입장에서는 AI 플랫폼 열 개를 지원하고 싶으면, 도구 스무 개 기준으로 무려 200개의 개별 통합을 만들어야 한다는 뜻이죠.

이게 바로 **M×N 문제**예요. AI 앱(M)과 도구(N)가 모두 늘어날수록 통합 비용이 기하급수적으로 커지는 구조예요. 비슷한 문제가 코드 편집기 세계에서도 있었어요. VS Code, Vim, IntelliJ 각각이 Python, Go, Rust 언어 서버를 전부 따로 지원해야 했을 때죠. 그 해결책이 LSP(Language Server Protocol)였고, MCP는 그 구조를 AI-도구 연결에 그대로 가져온 거예요.

MCP가 도입되면 M+N으로 줄어요. Slack이 MCP 서버를 하나만 만들면, MCP를 지원하는 모든 AI 플랫폼이 추가 작업 없이 Slack을 쓸 수 있어요. 개발자에겐 코드량이 줄고, 서비스 기업엔 유지보수 부담이 줄고, 사용자에겐 더 많은 AI 기능이 생기는 셈이에요.

타임라인을 보면 속도가 인상적이에요.

- **2024년 11월**: Anthropic, MCP 오픈소스 공개 (Python·TypeScript SDK + Google Drive, Slack, GitHub 등 초기 서버 포함)
- **2025년 2월**: AI 코딩 도구 Cursor가 MCP 최초 도입
- **2025년 3월**: OpenAI, ChatGPT MCP 통합 발표 → 업계 관심 폭발
- **2025년 4월**: Google, A2A 프로토콜 발표
- **2025년 12월**: MCP 거버넌스, Linux Foundation 산하 AAIF로 이전

18개월도 안 되는 기간에 사실상 표준이 된 거예요.

## MCP가 실제로 하는 일: 세 가지 핵심 기능

### 도구 연결: AI가 직접 "행동"하게 만드는 것

MCP의 기술 구조는 세 역할로 나뉘어요. **Host**(VS Code, Notion 같은 작업 환경), **MCP Client**(호스트에 설치된 플러그인), **MCP Server**(AI 모델에 맥락을 전달하는 중간 서버)로요.

실제로 Notion은 이미 Claude와 MCP로 연결돼 있어요. "이번 주 마케팅 일정 DB 만들어줘"라고 입력하면 Claude가 직접 Notion 데이터베이스를 생성해요. Blender는 MCP 서버를 통해 텍스트 프롬프트만으로 3D 모델링을 실행하고요. Zapier, Google Drive, Slack도 이미 MCP 호환 상태라 추가 개발 없이 바로 쓸 수 있어요.

구조의 핵심은 **Tool, Resource, Prompt** 세 가지예요.
- **Tool**: AI가 직접 실행하는 함수 (캘린더 일정 추가, 코드 배포 등)
- **Resource**: 읽기 전용 데이터 (파일, DB 내용 등)
- **Prompt**: 재사용 가능한 워크플로 템플릿

이 세 가지가 JSON-RPC 2.0 기반으로 통신해요.

### MCP vs A2A: 무엇이 다른가요?

2026년 현재 AI 에이전트 생태계엔 두 개의 핵심 프로토콜이 공존해요.

| 항목 | MCP | A2A |
|------|-----|-----|
| 개발사 | Anthropic | Google |
| 목적 | AI ↔ 도구 연결 | AI ↔ AI 연결 |
| 비유 | USB 표준 (기기-컴퓨터) | 사내 메신저 (직원-직원) |
| 발표 시점 | 2024년 11월 | 2025년 4월 |
| 거버넌스 이전 | 2025년 12월 (Linux Foundation) | 2025년 6월 (Linux Foundation) |
| 엔터프라이즈 파트너 | 전 주요 AI 기업 채택 | 100개 이상 기업 파트너 |
| 주요 인증 방식 | OAuth/Bearer Token | Agent Card |

MCP가 "AI와 도구"를 이어주는 프로토콜이라면, A2A는 "AI와 AI"가 서로 대화하게 해줘요. 예를 들어 고객 문의가 들어오면, 접수 에이전트가 MCP로 CRM 데이터를 읽고, A2A로 전문 처리 에이전트에게 작업을 넘기는 방식이에요. 두 프로토콜은 경쟁이 아니라 상호보완이에요.

### 보안: 편의 뒤에 숨은 리스크

MCP의 한계를 짚어야 해요. **보안은 프로토콜에 내장돼 있지 않아요.** 도구 실행 승인은 전적으로 Host 구현체의 책임이에요.

쉽게 말하면 이래요. MCP는 AI가 이메일을 보낼 수 있게 해주지만, "이 이메일을 보내도 되나요?"를 판단하는 건 MCP가 아니라 그 위에 올라탄 앱이 해야 해요. 기업에서 MCP 기반 에이전트를 도입할 때 별도 접근제어 설계가 필수인 이유예요.

## 누가, 어떻게 준비해야 할까요?

**개발자/엔지니어 팀**: 지금 당장 MCP 서버 하나 만들어보는 게 의미 있어요. TypeScript SDK가 가장 성숙도가 높고(Tier 1), Python도 동등한 수준이에요. 사내 레거시 시스템에 MCP 서버를 붙이는 것만으로 회사의 AI 에이전트가 그 시스템을 직접 조작할 수 있게 돼요.

**기업 의사결정자**: MCP+A2A 아키텍처는 부서별 AI 사일로 문제를 직접 해결해요. 마케팅 에이전트, 영업 에이전트, 재무 에이전트가 같은 인프라 위에서 데이터를 공유하고 작업을 넘길 수 있는 구조예요. 권장하는 접근법은 전사 일괄 도입이 아니라 부서 단위 파일럿 우선이에요. 다중 에이전트 실행 추적 시스템과 에이전트 간 통신 실패 대비 fallback 로직도 설계 단계부터 챙겨야 해요.

**일반 사용자**: 당장 코드를 짤 필요는 없어요. 그런데 "AI가 내 앱을 대신 조작한다"는 게 현실이 되는 시점이 생각보다 빠르게 오고 있어요. 내가 쓰는 앱이 MCP를 지원하는지, AI 에이전트에게 어느 수준의 권한을 줄 것인지 고민해둬야 해요. 이건 기술 지식이 아니라 권한 설정의 문제거든요.

**다음에 주시할 신호 세 가지**:
- Apple·Samsung 기기 OS 레벨 MCP 통합 발표 여부
- 국내 SaaS 서비스(토스, 카카오, 네이버)의 공식 MCP 서버 공개
- AAIF의 MCP 버전 업데이트 (현재 버전: `2025-11-25`, Tasks 기능 아직 실험적)

## 앞으로 6-12개월, 무엇이 바뀌나요?

MCP는 이미 기술 표준 경쟁에서 이겼어요. 남은 질문은 "얼마나 빠르게 일상에 들어오냐"예요.

- **2026년 하반기**: 의료·금융·마케팅 분야에서 MCP 기반 특화 에이전트 본격 등장 예상. 의료기록 조회, 리스크 평가, 이메일 자동 생성이 MCP로 연결될 가능성이 높아요.
- **2027년 초**: 멀티 에이전트 아키텍처가 기업 표준 인프라로 자리잡을 전망. MCP가 AI와 도구 사이의 연결을, A2A가 에이전트 사이의 협업을 담당하는 구조요.
- **열린 질문**: 보안 책임이 Host 구현체에 맡겨진 현재 구조가 기업 대규모 채택 단계에서 병목이 될 수 있어요. AAIF가 이 부분을 어떻게 표준화할지가 진짜 변수예요.

AI 에이전트 연결 표준 MCP, 일반인도 알아야 하는 이유는 결국 하나예요. 이건 "AI가 더 똑똑해지는 이야기"가 아니라 "AI가 내 데이터와 내 앱에 직접 손댈 수 있게 되는 이야기"거든요. 그 연결이 어떻게 설계되는지 알고 있어야, 내 권한을 제대로 설정할 수 있어요.
