코딩 한 줄 못 써도 웹 자동화를 해낼 수 있을까요? 2026년 9월 현재, 이 질문의 답이 조용히 바뀌고 있어요.

에이전트 브라우저 시장은 2024년 45억 달러에서 2034년 768억 달러로 성장할 전망이에요. 연평균 32.8% 성장률은, 이 영역이 단순한 개발자 장난감을 넘어섰다는 신호예요. 그런데 비개발자 입장에서 보면 "저도 쓸 수 있는 건가요?"라는 질문이 여전히 명확하지 않아요. 도구는 많아졌는데, 진입 장벽도 함께 낮아졌는지는 다른 문제니까요.

> **핵심 요약**
> - [Bright Data 리포트](https://brightdata.com/blog/ai/best-agent-browsers)에 따르면 에이전트 브라우저 시장은 2034년까지 768억 달러 규모로 성장할 전망이며, 비개발자용 노코드 도구가 핵심 성장 동력으로 부상하고 있어요.
> - Browser Use는 WebVoyager 벤치마크에서 89.1% 정확도를 기록하며 오픈소스 도구 중 최상위 성능을 보였지만, Python 환경 설정이 필요해 비개발자에게는 여전히 진입 장벽이 있어요.
> - Fly QA 같은 Chrome 확장 기반 노코드 도구는 클릭-녹화-재생 방식으로 QA 자동화를 코딩 없이 구현하고 있으며, 비개발자의 실제 업무 자동화 가능성을 보여줘요.
> - ChatGPT Atlas(2025년 10월 출시)와 Perplexity Comet은 무료 티어로 소비자 시장을 공략하며, AI 브라우저 자동화 도구를 비개발자도 쓸 수 있는 방향으로 생태계가 이동하고 있어요.

---

## 에이전트 브라우저, 그게 뭐예요?

전통적인 브라우저 자동화는 `Selenium`이나 `Playwright` 같은 라이브러리를 코드로 직접 짜는 방식이었어요. 버튼의 CSS 클래스를 찾아서, 클릭 이벤트를 스크립트로 정의하고, 사이트 구조가 바뀌면 처음부터 다시 짜야 했죠. 개발자가 아니면 시작조차 어려웠어요.

에이전트 브라우저는 달라요. LLM(대형 언어 모델)을 얹어서, "로그인하고 최근 주문 내역 엑셀로 뽑아줘" 같은 자연어 명령을 직접 실행해요. 사이트 구조가 바뀌어도 AI가 맥락을 파악해서 알아서 적응하고요.

결정적인 차이가 하나 더 있어요. 전통 자동화는 사이트가 조금만 바뀌어도 스크립트가 깨져요. 에이전트 브라우저는 CAPTCHA 자동 처리, 로그인 상태 유지, 멀티탭 관리까지 내장되어 있어요. [Bright Data 자료](https://brightdata.com/blog/ai/best-agent-browsers)에 따르면, Bright Data Agent Browser 하나만 해도 동시 세션 100만 개, 195개국 4억 개 이상의 IP를 지원해요. 규모 자체가 달라진 거죠.

2025년은 이 시장의 분기점이었어요. Browserbase가 2025년 6월 시리즈 B로 4,000만 달러를 조달하며 기업 가치 3억 달러를 인정받았고, ChatGPT Atlas와 Perplexity Comet이 각각 10월과 7월에 소비자용 무료 티어로 출시됐어요. 기업용 인프라 도구에서 일반 사용자 도구로 중심이 이동하기 시작한 거예요.

## 비개발자가 실제로 쓸 수 있는가: 세 가지 축으로 봐요

### 오픈소스 진영: 강력하지만 허들 있어요

[Browser Use](https://github.com/browser-use/browser-use)는 WebVoyager 벤치마크 586개 웹 태스크에서 89.1%를 달성했어요. ChatGPT Atlas의 87%보다 높은 수치로, 현재 공개 벤치마크 중 최상위예요. LangChain과 연동해서 Playwright 기반으로 크로미움, 파이어폭스, WebKit을 모두 돌릴 수 있고요.

문제는 진입 방식이에요. Python 환경 설정, pip 패키지 설치, LLM API 키 발급까지 최소 서너 단계를 개발자 없이 혼자 넘어야 해요. 성능은 최고인데, 비개발자 입장에서는 그 성능을 꺼내기 전에 막히는 셈이에요.

### 노코드 Chrome 확장: 비개발자의 현실적 출발점

[Eric's DevLog에 소개된 Fly QA](https://kyungyeon.dev/posts/131/)는 접근 방식 자체가 달라요. Chrome 확장 프로그램으로 설치하면, 녹화 버튼을 누르고 화면에서 동작을 수행한 뒤 저장하면 테스트 시나리오가 만들어져요. 코드 한 줄 없이요.

기술적으로는 Chrome 내장 Recorder를 확장해서 클릭, 입력, 네비게이션 이벤트를 캡처하고 커스텀 DSL로 변환해요. 로그인 같은 반복 흐름은 블록으로 저장해서 여러 시나리오에 불러올 수 있고, Slack 웹훅으로 테스트 결과 알림도 받을 수 있어요. AI가 녹화된 스텝을 요약해서 추가 검증 포인트까지 자동 제안해줘요.

한계는 명확해요. Playwright 기반 재생 엔진이 실시간 속도에 최적화되지 않아서, 티켓 구매 같은 타이밍이 중요한 작업엔 맞지 않아요. 정밀한 타이밍 이벤트도 녹화가 완벽하지 않고요. 하지만 QA 테스트나 반복 확인 작업이라면 비개발자도 충분히 써볼 수 있어요.

### 소비자용 AI 브라우저: 가장 쉽고, 가장 제한적이에요

ChatGPT Atlas와 Perplexity Comet은 설치도, API 키도 필요 없어요. 브라우저 열고 자연어로 "지난주 내 쇼핑몰 주문 목록 가져와줘" 하면 끝이에요. 비개발자에게 가장 낮은 진입 장벽이죠.

하지만 커스터마이징 범위가 좁아요. 반복 스케줄링, 외부 서비스 연동, 세밀한 조건 분기 같은 업무 자동화에는 아직 한계가 있어요.

### 도구 비교: 누구에게 뭐가 맞을까요?

| 기준 | Browser Use (오픈소스) | Fly QA (노코드 확장) | ChatGPT Atlas / Comet |
|------|----------------------|--------------------|-----------------------|
| 코딩 필요 여부 | Python 기본 지식 필요 | 불필요 | 불필요 |
| 벤치마크 성능 | WebVoyager 89.1% | 공개 수치 없음 | Atlas 87% |
| 설치 복잡도 | 높음 (pip, API 키) | 낮음 (Chrome 확장) | 매우 낮음 (계정만) |
| 커스터마이징 | 높음 | 중간 (블록 기반) | 낮음 |
| 비용 | API 비용 별도 | 사내 자체 개발 | 무료 티어 존재 |
| 적합 대상 | 개발자/데이터 팀 | 비개발자 QA 담당자 | 일반 소비자 |

비개발자라면 시작점은 Atlas나 Comet 같은 소비자 도구예요. 여기서 자동화의 감을 익히고, 업무에 반복 작업이 많다면 Fly QA 같은 노코드 Chrome 확장으로 올라가는 루트가 현실적이에요. Browser Use는 주변 개발자와 협업하거나, 어느 정도 기술적 배경이 있을 때 써볼 수 있어요.

## 실무에서 어떻게 접근할까요: 직군별로 달라요

**QA·운영 담당자라면** 지금 당장 써볼 수 있어요. Fly QA처럼 Chrome 확장 기반 노코드 툴은 반복 회귀 테스트를 코딩 없이 처리해줘요. Slack 알림 연동까지 되면 QA 보고 시간을 눈에 띄게 줄일 수 있고요. 다음 달 배포 사이클 전에 한 번 파일럿으로 돌려보는 게 좋아요.

**마케터·기획자라면** ChatGPT Atlas나 Perplexity Comet으로 시작해요. 경쟁사 가격 모니터링, 리뷰 수집, 콘텐츠 리서치 같은 단발성 작업에 유용해요. 다만 민감한 계정 자격증명을 넘기는 작업은 아직 보안 리뷰가 필요해요.

**개발팀이 있는 조직이라면** Browser Use를 검토할 때예요. 내부 워크플로우에 맞게 커스터마이징할 수 있고, Browserbase처럼 엔터프라이즈급 인프라와 연동하면 대규모 스크레이핑이나 RPA 파이프라인을 구축할 수 있어요.

**지켜볼 신호 세 가지:**
- Atlas·Comet의 무료 티어 기능 범위가 어디까지 확대되는지
- 노코드 도구들의 Playwright 엔진 속도 개선 로드맵
- 각국 규제 당국의 자동화 웹 접근에 대한 법적 해석

## 결론: 진입 장벽은 낮아졌지만, 완전히 사라진 건 아니에요

정리하면 이래요.

- 에이전트 브라우저 시장은 2034년까지 연 32.8% 성장이 예상돼요
- 비개발자가 쓸 수 있는 도구는 이미 존재하고, ChatGPT Atlas와 노코드 확장이 현실적 시작점이에요
- 오픈소스 최강자 Browser Use는 성능(89.1%)은 가장 높지만, 비개발자 친화성은 아직 한계가 있어요
- 업무 복잡도에 따라 도구를 단계적으로 올라가는 전략이 유효해요

앞으로 6~12개월 안에 소비자용 AI 브라우저 도구의 커스터마이징 범위가 더 넓어질 거예요. "AI 브라우저 자동화 도구 비개발자도 쓸 수 있나"라는 질문은, 2027년쯤엔 더 이상 질문거리가 아닐 수도 있어요. 지금 한 번이라도 써본 사람과 안 써본 사람의 차이가 그때 가서 확실히 드러날 거거든요.

여러분 팀에서 반복적으로 하는 웹 작업, 한 가지만 떠올려 보세요. 그게 자동화의 출발점이에요.
