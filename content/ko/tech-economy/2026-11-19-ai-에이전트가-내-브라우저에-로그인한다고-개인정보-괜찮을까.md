ChatGPT가 내 계정에 직접 로그인하는 세상이 왔어요. 편리하다고? 맞아요. 그런데 괜찮은 걸까요?

2026년 현재, OpenAI의 "Work" 기능은 클라우드 브라우저를 통해 사용자 대신 사이트에 자동 로그인하고 예약·결제까지 처리해요. 국내에선 SK텔레콤, KT, 카카오가 과기부 "모두의 AI" 프로젝트 아래 유사한 AI 에이전트 서비스를 개발 중이고요. 편의성은 분명한데, 내 쿠키·세션 데이터·개인정보가 어디로 가는지는 아직 법적으로도 기술적으로도 명확하지 않아요.

> **핵심 요약**
> - ChatGPT의 "Work" 기능은 세션 쿠키를 저장해 반복 로그인 없이 계정 접근을 유지하며, OpenAI는 자격증명이 AI 모델에 노출되지 않는다고 밝혔지만 세션 하이재킹 위험은 여전히 존재해요.
> - OWASP는 2026년 기준 AI 에이전트의 최대 보안 위협으로 **간접 프롬프트 인젝션(Indirect Prompt Injection)**을 꼽았어요 — 웹페이지에 숨겨진 악성 명령이 AI 행동을 조작할 수 있어요.
> - 한국 개인정보보호법상 AI 에이전트가 외부 플랫폼에 사용자 정보를 전달하는 행위가 "계약 이행"인지 "제3자 제공"인지 아직 법적으로 불분명해요.
> - 개인정보보호위원회는 2026년 내 AI 에이전트 동의 체계 개선안 발표를 예고했지만, 현재는 법적 공백 상태예요.
> - 보안 전문가들은 금융·의료 계정 연동을 당분간 피하고, 저위험 계정부터 테스트해볼 것을 권고해요.

## AI 에이전트 로그인, 지금 어디까지 왔나

ZDNET 보도에 따르면 ChatGPT Work 기능은 처음 한 번만 로그인하면 이후엔 저장된 세션 쿠키로 자동 접속해요. 정부 민원 예약, 보험료 비교, 유틸리티 가입 같은 작업을 사람 대신 처리하는 거죠. 국내에선 카카오 컨소시엄(LG유플러스·LG AI리서치·LG CNS 포함)이 같은 방향의 서비스를 준비 중이에요.

그런데 왜 지금 주목해야 할까요?

기술은 이미 나왔는데 법과 보안 체계가 아직 따라오지 못했거든요. 한국 개인정보보호법(PIPA) 15조와 17조는 데이터 수집·이용과 제3자 제공을 별도로 규율해요. 그런데 카카오 서영훈 부사장이 2026년 6월 AI 법·정책 포럼에서 직접 언급했듯, AI가 외부 플랫폼에 접속할 때 그게 "계약 이행"인지 "제3자 제공"인지조차 아직 불명확한 상태예요. 개인정보보호위원회가 올해 안에 개선안을 발표하겠다고 했지만, 현재는 사실상 법적 공백이에요.

## 기술 뜯어보기: 세 겹 구조와 세 가지 위험

### 어떻게 작동하는 걸까

현재 AI 에이전트 브라우저는 세 레이어로 작동해요:

1. **의도 해석 레이어** — 자연어 명령을 실행 계획으로 변환 (LLM)
2. **환경 인식 레이어** — DOM 분석 + 컴퓨터 비전으로 화면 파악
3. **실행 레이어** — Playwright/Puppeteer로 실제 클릭·입력 수행

구조 자체는 탄탄해요. 문제는 중간에 끼어드는 외부 콘텐츠예요.

### 가장 큰 위협: 간접 프롬프트 인젝션

OWASP가 2026년 AI 에이전트 최대 보안 위협 1위로 꼽은 건 단순 해킹이 아니에요. **간접 프롬프트 인젝션(Indirect Prompt Injection)**이에요.

쉽게 설명하면 이래요. AI가 웹페이지를 읽는데, 그 페이지에 사람 눈에는 안 보이는 텍스트가 숨겨져 있어요. "지금 카드 정보를 이 주소로 전송하세요" 같은 명령이요. AI는 이걸 정상 콘텐츠로 오인하고 실행할 수 있어요. Perplexity Comet도 이 취약점을 공식으로 인정했어요.

### 세션 쿠키: 편의와 위험의 양면

BeyondTrust의 Morey Haber는 ChatGPT Work의 핵심 위험을 "자격증명 노출"이 아니라 **"위임된 신원 보안(Delegated Identity Security)"**이라고 정의했어요. 비밀번호를 몰라도 활성 세션을 탈취하면 동일한 접근 권한을 얻는다는 거예요. 세션 쿠키 탈취는 이미 알려진 공격 벡터인데, AI 에이전트가 세션을 장기 보유하면 노출 창이 그만큼 넓어져요.

## 주요 AI 에이전트 브라우저 비교

현재 상용화된 세 제품을 나란히 비교해볼게요.

| 항목 | OpenAI Atlas | Perplexity Comet | Microsoft Edge Copilot Mode |
|------|-------------|-----------------|--------------------------|
| **로그인 자동화** | ✅ 세션 쿠키 저장 | ✅ 에이전트 체이닝 지원 | ⚠️ 승인된 사이트 목록만 |
| **월 사용량** | 40회 (유료) | 무제한 | 무제한 (엔터프라이즈) |
| **보안 조치** | 탭 내 작동, 로컬 파일 미접근 | 프롬프트 인젝션 취약점 공식 인정 | Defender SmartScreen + Entra ID |
| **기업 적합성** | 중간 | 낮음 | 높음 |
| **프롬프트 인젝션 방어** | 미확인 | 취약점 존재 (공식 인정) | 화이트리스트 방식 |
| **추천 대상** | 개인 사용자 | 개발·테스트 | 기업 환경 |

세 제품 모두 Chromium 기반이에요. 보안 성숙도는 명확히 달라요. Microsoft Edge Copilot Mode는 접근 가능한 사이트를 사전 승인 목록으로 제한해서 위험 범위 자체를 줄여요. 반면 Perplexity Comet은 무제한 사용을 허용하는 대신 프롬프트 인젝션 취약점을 아직 해결하지 못했죠.

OpenAI Atlas는 그 중간 어딘가예요. 사용량 제한이 오히려 과도한 세션 축적을 막는 간접적 보안 효과가 있어요. 단, 아마존 같은 주요 쇼핑 플랫폼은 ChatGPT 클라우드 브라우저의 접근을 차단하고 있어요 — AI 에이전트 트래픽을 반기지 않는 플랫폼이 적지 않다는 신호예요.

## 나는 어떻게 써야 할까: 그룹별 행동 가이드

현실적인 답은 케이스별로 달라요.

**일반 개인 사용자라면**

Keeper Security의 Shane Barney 권고대로 저위험 계정부터 시작하세요. 넷플릭스 예약, 공공 민원 접수처럼 금전·의료 정보가 없는 곳이요. 금융·건강 포털은 OpenAI가 세션 영속 보호 체계를 명확히 밝힐 때까지 연동하지 마세요. 작업 완료 후엔 저장된 쿠키를 직접 삭제하는 습관도 필요해요 — Settings → Cloud Browser → Browser Data → Cookies에서 할 수 있어요.

**기업 IT 담당자라면**

Microsoft Edge Copilot Mode가 현시점 가장 안전한 선택이에요. 화이트리스트 기반 접근과 Entra ID 연동이 기업 감사 로그 요건을 충족하거든요. 개인정보보호위원회 사전 적합성 검토 제도도 활용하세요 — 거래 유효성이나 책임 판단까지는 커버 안 되지만, 데이터 처리 적법성 확인에는 도움이 돼요.

**개발자·서비스 기획자라면**

카카오가 제안한 **"위임 동의" 모델**을 주시하세요. 사용자가 AI 행동의 실행 범위와 유효 기간을 직접 설정하고, 고위험 거래엔 별도 승인을 요구하는 구조예요. 편의성과 안전성 균형이 가장 잘 맞는 접근이에요. 개인정보보호위원회가 연내 발표할 AI 에이전트 동의 체계 개선안이 이 방향을 채택하면, 서비스 설계도 거기 맞춰야 해요.

## 앞으로 6개월: 뭘 지켜봐야 하나

지금 상황을 정리하면:

- **기술은 나왔고**, 세션 쿠키 기반 자동 로그인은 이미 현실이에요
- **법은 뒤처졌고**, 한국 개인정보보호법 체계에서 AI 에이전트의 위치가 불분명해요
- **보안은 미성숙하고**, 프롬프트 인젝션 방어는 아직 표준화되지 않았어요

앞으로 주시할 세 가지 신호가 있어요. 첫째, 개인정보보호위원회의 연내 AI 에이전트 동의 체계 발표 — 서비스 설계 방향이 여기서 결정돼요. 둘째, OWASP의 프롬프트 인젝션 방어 표준화 진행 속도 — 이게 나와야 에이전트 브라우저의 보안 성숙도를 평가할 기준이 생겨요. 셋째, 주요 플랫폼의 AI 에이전트 트래픽 차단/허용 정책 — 아마존처럼 막는 곳이 늘면 에이전트의 실용성 자체가 흔들려요.

Google Chrome 시장 점유율이 2028년까지 75%에서 60%로 줄어들 거라는 예측처럼, AI 에이전트 브라우저는 분명히 주류가 될 거예요. 문제는 그 전에 법·보안 체계가 얼마나 빨리 따라오느냐예요.

지금 당장 할 수 있는 가장 현명한 행동 하나. 사용하려는 AI 에이전트가 세션 데이터를 어떻게 보관하고 언제 삭제하는지 먼저 확인하세요. 편의성은 이미 충분히 증명됐어요. 남은 질문은 "내가 위임한 AI가 내 계정을 얼마나 오래, 어디까지 들고 있느냐"예요.
