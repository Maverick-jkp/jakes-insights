## AI 에이전트 기억 초기화 문제, 왜 지금 더 거슬리냐면

사실 이 문제는 어제오늘 일이 아니에요. ChatGPT가 나온 2022년부터 "왜 어제 한 말을 모르냐"는 불만은 있었거든요. 그런데 2026년엔 맥락이 달라졌어요.

지금은 AI를 쓰는 방식 자체가 바뀌었어요. 단순한 질의응답이 아니라, 며칠·몇 주에 걸쳐 하나의 프로젝트를 같이 끌어가는 **에이전트형 작업**이 주류가 됐죠. 코드 리팩토링, 문서 초안, 데이터 파이프라인 설계 — 이런 작업은 한 세션에 끝나지 않아요.

여기에 디바이스 다양화가 겹쳤어요. 출근길엔 스마트폰, 사무실에선 데스크톱, 집에서는 개인 노트북. 세 군데에서 같은 에이전트를 쓰는 게 이제 흔한 패턴인데, 디바이스 바꿀 때마다 대화 처음부터 해야 하나 — 이 질문이 2026년에 더 현실적인 고통이 된 이유예요.

**AI 에이전트 기억 초기화 문제**의 핵심은 단순히 "기억이 없다"가 아니에요. 기억을 *어떻게* 유지하느냐에 따라 도구마다, 심지어 같은 도구의 버전마다 동작이 달라진다는 게 문제예요. 지금부터 그 차이를 뜯어볼게요.

## 기억이란 게 AI 에이전트한테 어떤 의미인가

기억에는 사실 네 가지 개념이 섞여 있어요.

1. **세션 재개** — 기존 대화창으로 돌아가는 것
2. **컨텍스트 압축** — 긴 대화를 요약해서 토큰을 아끼는 것
3. **정적 지시 파일** — 매 새 세션마다 자동으로 불러오는 규칙 파일
4. **크로스 세션 메모리** — 에이전트가 스스로 쓰고 읽는 장기 기억

[DEV Community 분석](https://dev.to/izgorodin/my-llm-agents-forget-conversation-history-when-i-restart-them-how-do-i-fix-this-2c4c)에 따르면, 위 다섯 도구 모두 1번(세션 재개)은 지원해요. 문제는 대부분의 사용자가 이 기능을 쓰지 않는다는 거예요. 새 대화를 여는 게 더 직관적으로 느껴지니까요.

[Hindsight 실험실 아티클](https://newfaces.tistory.com/66)이 측정한 수치가 의미 있어요. 주 5회 세션 기준, 매번 기술 스택·선호 설정·이전 결정을 재입력하면 **한 달에 40~60분**이 그냥 사라져요. 그리고 같은 프로젝트를 3회 이상 연속으로 하는 경우에만 메모리 인프라를 따로 구축할 가치가 생겨요. 그 아래는 그냥 손으로 붙여넣는 게 빨라요.

## 도구별 기억 유지 방식 비교

### 주요 AI 코딩 도구 메모리 현황 (2026년 11월 기준)

| 항목 | Claude Code | Cursor | VS Code (Copilot) | Codex | Windsurf |
|------|-------------|--------|-------------------|-------|----------|
| **세션 재개** | 5가지 진입점 | CLI만 | 인터페이스에서 가능 | CLI + 인터페이스 | CLI + 인터페이스 |
| **컨텍스트 압축** | 사용자가 선택 (요약/전체/취소) | 메커니즘 있음, 세부 미공개 | 정보 손실 인정, 임계값 미공개 | 미공개 | 미공개 |
| **크로스 세션 메모리** | 기본 활성화, 4개 카테고리 | v1.0 도입 → v2.1.x에서 관리 UI 삭제 | 실험적, 기본 활성화, 3개 범위 | 있음, 기본 비활성화 | Cascade 에이전트만 (현재 기본 에이전트 미지원) |
| **디바이스 간 동기화** | 프로젝트 범위로 제한 | 불확실 | 로컬 범위 | 불확실 | 미지원 |

출처: [DEV Community 세션 메모리 분석](https://dev.to/izgorodin/my-llm-agents-forget-conversation-history-when-i-restart-them-how-do-i-fix-this-2c4c)

### 세 가지 접근법: 뭘 골라야 할까

**접근법 A — 세션 재개 (지금 당장 쓸 수 있는 것)**

- **장점**: 추가 설정 없음, 기존 도구로 가능, 대화 흐름 유지
- **단점**: 디바이스 바꾸면 세션이 끊김, 1시간 이상 유휴 시 압축 발생
- **맞는 경우**: 같은 디바이스에서 단기 프로젝트 작업할 때

**접근법 B — 정적 지시 파일 (`.cursorrules`, `CLAUDE.md` 등)**

- **장점**: 모든 새 세션에 자동 로드, 디바이스 간 Git으로 동기화 가능
- **단점**: 에피소드 기억(지난번에 뭘 했는지)은 저장 안 됨, 수동 관리 필요
- **맞는 경우**: 기술 스택·코딩 스타일처럼 변하지 않는 규칙 저장

**접근법 C — 로컬 메모리 인프라 구축**

[Hindsight 실험실](https://newfaces.tistory.com/66)에서 직접 구현한 방식이에요. Python 기본 라이브러리(`json`, `pathlib`, `datetime`)만 써서 작동하고, 데이터가 로컬 밖으로 나가지 않아요. Ollama(로컬 LLM)와 연결하면 코드 세 줄로 과거 메모리를 시스템 프롬프트에 주입할 수 있어요.

- **장점**: 클라우드 프라이버시 위험 없음, 에피소드 로그 + 사용자 선호 벡터 저장 모두 가능
- **단점**: 직접 구축해야 함, 민감한 데이터엔 암호화·파일 잠금 별도 필요
- **맞는 경우**: 데이터 주권이 중요한 개발자, 장기 프로젝트

## 디바이스 바꿀 때마다 대화 처음부터 해야 하나: 세 가지 시나리오

### 시나리오 1 — 같은 도구를 여러 디바이스에서 쓸 때

지금 당장 가장 현실적인 해법은 **정적 지시 파일을 Git으로 관리**하는 거예요. `CLAUDE.md`나 `.cursorrules` 파일에 프로젝트 맥락·기술 스택·결정 사항을 적어두고 레포에 커밋하면, 어느 디바이스에서 풀받든 에이전트가 그 파일을 먼저 읽어요.

에피소드 기억(지난번에 어디까지 했는지)까지 넘기려면 `CHANGELOG.md` 스타일로 의사결정 로그를 함께 관리하는 게 현실적이에요.

### 시나리오 2 — Cursor나 Windsurf처럼 메모리 기능이 불안정한 도구

Cursor는 v1.2에서 메모리를 일반 공개했다가, 2025년 11월 v2.1.x에서 관리 UI를 조용히 제거했어요. 체인지로그 언급도 없었고, 벤더 답변도 엇갈렸어요. Windsurf는 현재 기본 에이전트(Devin Local)가 메모리를 아예 지원하지 않아요. 이런 도구를 쓴다면 도구 자체의 메모리에 기대지 말고, 외부 파일 기반 접근법으로 돌아가는 게 안전해요.

### 시나리오 3 — 클라우드 AI 서비스 (ChatGPT, Claude.ai 등)

Anthropic이 2026년 8월에 채팅 제품 메모리를 통합했어요. 그런데 이게 Claude Code 터미널 에이전트에는 적용이 안 된다는 점, 헷갈리기 쉬워요. 채팅창에서 대화한 내용이 에이전트 세션에 넘어가지 않아요. 두 메커니즘은 별개예요.

ChatGPT는 계정 기반 메모리를 쓰기 때문에 디바이스가 달라도 같은 계정이면 기억이 이어져요. AI 에이전트 기억 초기화 문제를 최소화하려면, 지금 단계에선 계정 기반 클라우드 서비스가 디바이스 간 연속성에서 가장 단순한 선택이에요.

## 앞으로 6~12개월, 뭘 봐야 하나

**정리하면 이래요:**

- 모든 주요 코딩 에이전트가 세션 재개를 지원하지만, 디바이스 간 동기화는 여전히 도구마다 달라요
- 월 40~60분의 맥락 재입력 비용은 작아 보여도, 프로젝트가 길어질수록 누적 손실이 커요
- 메모리 기능의 안정성은 도구 버전에 따라 언제든 바뀔 수 있어요 — Cursor v2.1.x 사례처럼요
- 가장 믿을 수 있는 방법은 Git으로 관리하는 정적 지시 파일이에요. 도구가 바뀌어도 파일은 남으니까요

앞으로 주시할 신호는 하나예요. **MCR(Memory Context Registry)** 같은 에이전트 간 표준 메모리 형식이 나오는지예요. 현재 각 도구가 독자 형식을 쓰는 탓에 Cursor에서 쌓은 맥락을 Claude Code로 가져오지 못해요. 이 호환성 문제가 해결되는 시점이 "디바이스 바꿀 때마다 대화 처음부터 해야 하나"라는 질문이 사라지는 시점이기도 해요.

지금 당장 할 수 있는 한 가지를 고른다면 — 오늘 작업 중인 프로젝트 레포에 `AI_CONTEXT.md` 파일 하나 만들어서 에이전트한테 "이 파일부터 읽어"라고 말해보세요. 복잡한 인프라 없이도, 내일 다른 디바이스에서 열어도 같은 출발점에서 시작할 수 있어요.
