Claude Code 다섯 창, Codex 세 창. 2026년 중반 개발자 커뮤니티에서 흔히 보이는 셋업이에요. 근데 이걸 "일반인"도 쓸 수 있을까요?

## 왜 지금 이 질문인가요

구독료가 쌓이고 있어요. Claude Pro, ChatGPT Plus, GitHub Copilot — 월 $60~100를 각각의 AI 에이전트에 쓰는 개발자가 2026년 들어 급격히 늘었어요. 그런데 이상한 점이 하나 있어요. 각 에이전트를 따로따로 쓰면서 같은 프롬프트를 복사해 붙여넣는 작업을 반복하고 있다는 거죠.

[Lun 개발자의 soonsoon blog](https://soonsoon.io/lun-multi-ai-agent-cli-tool/)에 따르면 이게 개발자들이 실제로 겪는 가장 흔한 불편이에요. Claude Code, Kiro, Copilot, Codex — 각각 다른 탭에 열어두고 같은 질문을 복붙하는 거요. 그 사람이 직접 Lun이라는 도구를 만든 이유이기도 해요.

여기에 2026년 중반 Anthropic과 OpenAI가 rate limit를 더 조이면서 상황이 복잡해졌어요. 에이전트를 많이 쓰고 싶은데, 한 계정으로는 한계가 있고, 계정을 여러 개 쓰려면 관리가 번거롭죠.

이 글에서 살펴볼 것들:

- 병렬 에이전트 도구 세 가지가 각각 어떤 문제를 풀었나
- 실제 쓸 만한 기준선 (3개 이상, 5분 이상)
- 비개발자가 진짜 쓸 수 있는지 여부
- 지금 당장 뭘 해봐야 하는지

> **핵심 요약**
> - [Herdr](https://qjc.app/en/blog/herdr-agent-runtime)는 Rust로 만든 터미널 워크스페이스 매니저로, 출시 137일 만에 GitHub 스타 약 2만 7천 개를 받았고, 에이전트 3개 이상을 5분 이상 돌릴 때 체감 효과가 나온다고 명시하고 있어요.
> - [Orca](https://qjc.app/blog/orca-parallel-agents)는 하나의 프롬프트를 여러 에이전트에 동시 배포하고 결과를 비교하는 fan-out 방식을 쓰는데, 에이전트를 N개 돌리면 API 쿼터도 N배 소비돼요.
> - [Lun](https://soonsoon.io/lun-multi-ai-agent-cli-tool/)은 2026년 5월 공개된 CLI 도구로, VS Code 확장까지 지원하면서 진입장벽을 낮췄지만 아직 초기 단계예요.
> - 세 도구 모두 "일반인"보다 "AI 에이전트를 이미 쓰는 개발자"를 주요 대상으로 설계됐어요.

## 세 도구, 세 가지 접근법

### Herdr: 터미널 창들의 교통정리

Herdr가 풀려는 문제는 딱 하나예요. "지금 어떤 에이전트가 내 입력을 기다리고 있나?"

[QJC의 Herdr 분석](https://qjc.app/en/blog/herdr-agent-runtime)에 따르면 Herdr는 AI 에이전트 자체가 아니에요. 에이전트들을 관리하는 "컨트롤 패널"이에요. Rust로 만들어서 바이너리 용량이 10MB 정도밖에 안 되고, 설치 의존성도 없어요.

에이전트 상태를 다섯 가지로 추적해요: **blocked(내 입력 대기), working(처리 중), done(완료), idle(대기 중), unknown**. 이 상태가 창 단위 → 탭 단위 → 프로젝트 단위로 올라오는 구조예요. 덕분에 창 열여섯 개를 열어놔도 "지금 뭘 봐야 하나"를 한눈에 알 수 있죠.

Claude Code, Codex, Cursor Agent CLI, GitHub Copilot CLI, Devin, Grok CLI 등 열여덟 가지 에이전트를 자동으로 인식해요. Git worktree도 기본 지원해서, 여러 브랜치에서 동시에 작업해도 파일 충돌이 없어요.

출시 137일 만에 GitHub 스타 약 2만 7천 개, 포크 1,885개. 2026년 8월 6일에는 Y Combinator 합류를 발표했어요. 그런데 핵심 개발자가 한 명이라는 점, Windows 지원이 아직 베타라는 점은 주목할 부분이에요.

### Orca: "팬아웃"으로 에이전트 비교하기

[QJC의 Orca 분석](https://qjc.app/blog/orca-parallel-agents)을 보면 Orca의 가장 차별화된 기능은 fan-out 워크플로예요. 같은 프롬프트를 여러 에이전트에게 동시에 보내고, 결과를 나란히 놓고 비교한 뒤, 가장 좋은 걸 골라 머지하는 방식이에요.

Stably AI(YC W2022)가 만든 4인 팀 프로젝트로, 앱 자체는 무료예요. 대신 Claude Pro/Max나 ChatGPT 구독을 본인이 직접 연결하는 "BYO 구독" 방식이에요.

2026년 7월 기준 GitHub 스타 약 1만 4천 개, 버전은 v1.4.128로 매일 릴리즈가 올라오고 있어요.

단점도 명확해요. 에이전트 N개를 동시에 돌리면 API 쿼터도 N배 소비돼요. 속도를 얻는 대신 사용량을 쓰는 거죠. Anthropic과 OpenAI가 rate limit를 조인 2026년 중반 타이밍에 계정 핫스왑 기능이 붙은 건 그래서 의미 있는 선택이에요.

### Lun: "논어"에서 이름 딴 CLI

가장 가볍고 직접적이에요. [soonsoon blog](https://soonsoon.io/lun-multi-ai-agent-cli-tool/)에 따르면 Lun(論)은 같은 프롬프트를 여러 에이전트에게 동시에 던지고, 응답을 나란히 보여주는 CLI 도구예요. 이름이 논어(論語)에서 왔는데, "여러 관점을 모아 판단한다"는 아이디어를 반영한 거예요.

2026년 5월 28일 서울 COEX에서 열린 GitHub After Dark 행사에서 처음 공개됐어요. VS Code 확장도 있어서 GitHub Copilot 인터페이스에서 직접 호출할 수 있어요.

다만 에이전트마다 내부 작동 방식이 달라서 성능 일관성이 아직 고르지 않다고 개발자가 직접 밝히고 있어요. 현재 개발자가 개인적으로 쓰면서 계속 업데이트하는 초기 단계예요.

## 세 도구 비교: 무엇이 다른가

| 항목 | Herdr | Orca | Lun |
|------|-------|------|-----|
| **핵심 기능** | 에이전트 상태 모니터링 | 팬아웃 + 결과 비교 | 병렬 프롬프트 디스패치 |
| **UI 형태** | 터미널 TUI | 데스크탑 앱 + 웹터미널 | CLI + VS Code 확장 |
| **지원 에이전트 수** | 18개 | 30개+ | Claude Code, Kiro, Copilot, Codex 등 |
| **Git worktree** | 기본 지원 | 지원 | 미지원 |
| **모바일 지원** | 없음 | iOS/Android (데스크탑 연결 필요) | 없음 |
| **라이선스** | Apache-2.0 (v0.8.0~) | MIT | 오픈소스 |
| **팀 규모** | 핵심 1인 | 4인 (Stably AI) | 개인 개발자 |
| **GitHub 스타 (2026)** | ~27,000 | ~14,000 | 공개 초기 |
| **가장 적합한 상황** | 에이전트 3개+ 동시 모니터링 | 같은 문제에 여러 에이전트 답 비교 | 간단한 멀티 에이전트 쿼리 |

세 도구 모두 "에이전트를 이미 쓰는 사람"을 위한 도구예요. 진입 허들이 다를 뿐이에요. Lun은 `npm install` 수준의 CLI 경험이 있으면 쓸 수 있고, Orca는 앱 설치가 익숙하면 돼요. Herdr는 터미널에 익숙하지 않으면 처음 설정에서 막힐 가능성이 높아요.

trade-off도 있어요. Orca의 팬아웃은 강력하지만 쿼터를 두 배, 세 배 태워요. Herdr의 상태 추적은 정밀하지만 Claude Code와 Codex에서는 화면 파싱 방식이라 간혹 오탐이 있어요. Lun은 가볍지만 에이전트 간 성능 편차가 아직 커요.

## 일반인이 쓰기엔 아직 무리일까요?

여기서 "일반인"을 어떻게 정의하느냐가 갈려요.

**터미널을 쓸 줄 아는 개발자라면** 지금 당장 쓸 수 있어요. Herdr나 Orca 중 하나를 골라서 시작하는 게 현실적이에요. Herdr의 기준선이 명확한 편인데, 에이전트 3개 이상, 각 작업이 5분 이상 걸릴 때 체감 효과가 나온다고 나와 있어요. 그 아래라면 tmux에 훅 하나 거는 것과 차이가 크지 않아요.

**코딩 도구를 간간이 쓰는 비개발자라면** Orca가 그나마 현실적이에요. UI가 있고, 앱으로 설치하고, 기존 Claude/ChatGPT 구독을 연결하면 되니까요. 다만 fan-out 결과를 보고 "어느 게 더 나은가"를 판단하는 건 여전히 맥락 이해가 필요해요.

**터미널이 낯선 일반인이라면** 아직은 일러요. 세 도구 모두 에이전트를 이미 쓰고 있고, 그 에이전트가 뭘 하는지 대략 아는 사람을 전제하고 있어요. 2026년 하반기 기준, 이 도구들은 "AI 코딩 에이전트 여러 개 동시에 돌리기"의 복잡성을 줄이는 방향으로 가고 있지만, "일반인도 쓸 수 있나"라는 질문의 답은 아직 "조건부 가능"이에요.

앞으로 주시할 신호가 세 가지 있어요:

- **Herdr의 YC 이후 행보**: 무료 오픈소스에서 유료 플랜으로 갈 가능성이 높아요. Hacker News 커뮤니티도 이미 이 우려를 제기했고요.
- **rate limit 정책 변화**: Anthropic과 OpenAI가 2026년 중반에 한 번 조였는데, 한 번 더 조이면 계정 핫스왑 기능의 가치가 바뀌어요.
- **Lun의 SAM 상용화**: 개발자가 내부적으로 운영 중인 SAM(여러 모델 라우팅 서비스)을 연말 공개 예정이라고 밝혔어요. 나오면 Lun의 성격이 꽤 달라질 수 있어요.

## 결론: 타이밍이 맞는 사람부터 써볼 만해요

정리하면 이래요:

- 에이전트 여러 개를 이미 쓰고 있고, 탭 전환에 피로감을 느낀다면 → **Herdr** 먼저
- 같은 문제에 여러 에이전트 답을 비교하고 싶다면 → **Orca**
- VS Code에서 간단하게 멀티 에이전트 쿼리를 써보고 싶다면 → **Lun**
- 아직 에이전트 하나도 제대로 안 써봤다면 → 먼저 Claude Code 하나부터

"AI 코딩 에이전트 여러 개 동시에 돌리기, 일반인도 쓸 수 있나"라는 질문에 솔직하게 답하면: 아직은 얼리어답터의 영역이에요. 도구는 빠르게 좋아지고 있지만, 에이전트를 먼저 이해해야 관리 도구가 의미 있거든요.

다음 6개월이 중요한 건, 세 도구 모두 아직 v1.0 전후예요. 지금 써보는 사람이 나중에 "당연한 워크플로"를 먼저 갖추는 셈이에요. 여러분은 에이전트 몇 개를 동시에 돌리고 있나요?
