IT 담당자 두 명이 Slack 채널에서 티켓을 받고, 분류하고, 처리하고 있어요. 그런데 어느 날 Slackbot이 "이 요청은 제가 처리할게요"라고 끼어드는 상황. SF 얘기가 아니에요. 지금 실제로 일어나고 있는 일이에요.

> **핵심 요약**
> - Slack은 2026년 Dreamforce에서 AI 에이전트 기반 업무 허브로 공식 전환을 선언했고, 하루 처리 메시지가 80억 건을 넘어섰어요
> - Slackbot 월 활성 사용자 150만 명, Nubank는 연간 100만 시간을 절감했는데, 이건 IT 담당자 수백 명분의 업무량이에요
> - AI가 IT 티켓 처리, 계정 비활성화, 온보딩 자동화를 맡기 시작하면서 1-3인 IT팀의 역할 전환이 현실 문제가 됐어요
> - Ando처럼 에이전트 네이티브 플랫폼이 등장하면서 Slack조차 경쟁 압박을 받고 있고, 도구 선택이 IT 전략의 핵심이 됐어요
> - "대체"보다 "재배치"가 정확한 표현이에요. 문제는 누가 먼저 전환점을 잡느냐예요

## 1. 지금 눈앞에 벌어지는 상황

[Dreamforce 2026 발표](https://m.news.nate.com/view/20260918n03910)에서 Salesforce는 Slack을 "에이전틱 엔터프라이즈의 현관문"으로 공식 재정의했어요. 업그레이드된 Slackbot은 단순 Q&A를 넘어서 Salesforce CRM 데이터를 참조해 고객 계정 이탈 위험을 감지하고, 담당자를 재배정하고, 이메일 초안까지 작성해요. Salesforce 내부 영업팀의 90%가 CRM에 직접 로그인하지 않고 Slackbot으로 업무를 처리하고 있죠.

> **First check:**
> 지금 귀사 Slack에 Slackbot이 활성화돼 있고, 워크플로우 빌더에 IT 관련 자동화 규칙이 하나라도 있다면, 이미 AI가 일부 IT 업무를 처리하고 있는 상태예요. `/slackbot` 명령어를 치거나 워크플로우 관리 탭에서 30초 안에 확인할 수 있어요.

이게 단순 편의 기능이 아니에요. 브라질 디지털 은행 Nubank는 Slackbot으로 연간 100만 시간을 절감했어요. 50명 규모 IT팀 한 팀이 20년 동안 할 일을 1년 만에 처리한 셈이에요. 중소기업 IT 담당자 입장에서 남 얘기처럼 안 들리는 이유가 있죠.

## 2. AI 에이전트가 실제로 처리하는 IT 업무 세 가지

### IT 티켓 자동 분류 및 1차 해결

**지금 상황 확인하기:**
Slack 워크플로우 빌더에서 `자동화 → 트리거 목록` 확인. "특정 단어가 포함된 메시지" 트리거가 IT 채널에 설정돼 있으면 이미 작동 중이에요.

```bash
# Slack API로 워크플로우 트리거 확인
slack triggers list --app-id YOUR_APP_ID
```

Slackbot은 "비밀번호 초기화 요청", "VPN 접속 안 됨" 같은 반복 요청을 자동 감지해서 처리해요. [Dreamforce 2026](https://m.news.nate.com/view/20260920n16221)에서 공개된 Slackforce Surfaces 기능은 자연어 요청만으로 실시간 대시보드를 생성하고 외부 서비스 데이터까지 연동해요.

IT 담당자 업무의 40-60%는 반복 요청이에요. 그 부분이 먼저 자동화돼요.

### MCP 연동으로 IT 인프라 직접 제어

**확인 방법:**
Slack 관리자 페이지 `설정 → 앱 관리 → MCP 연동` 탭. 연결된 외부 서비스 목록을 보면 에이전트의 접근 범위를 파악할 수 있어요.

```bash
# 연결된 MCP 서버 확인
slack apps list --verified
```

Salesforce는 Slack에 MCP(Model Context Protocol) 서버를 연결해 Sales Cloud, Service Cloud, Agentforce, Tableau를 직접 붙였어요. IT 에이전트가 이 채널을 통해 사용자 계정 상태를 조회하고, 권한을 변경하고, 서비스 티켓을 생성할 수 있게 된 거예요. 계정 생성·비활성화·권한 변경 같은 루틴 작업이 자동화 범위 안으로 들어왔다는 뜻이에요.

### 에이전트 네이티브 플랫폼의 등장

**확인 방법:**
팀 내 개발자가 외부 AI 에이전트를 이미 연동해 쓰고 있는지 체크하세요. Slack 관리 콘솔 `보안 → 앱 승인 현황`에서 확인할 수 있어요.

[Ando라는 스타트업](http://ainet.link/28841)은 아예 다른 방향으로 갔어요. Accel, Index Ventures, Emergence로부터 2,000만 달러를 유치해서 AI 에이전트가 팀원처럼 채널을 자율 탐색하고, 태그 없이도 대화에 참여하고, 중복 채널을 병합하는 플랫폼을 만들었어요. 현재 15개국 소프트웨어·금융·부동산 기업이 쓰고 있죠.

[TechCrunch 보도](https://techcrunch.com/2026/09/24/ando-eyes-slack-as-it-builds-team-messaging-platform-for-humans-and-agents-to-work-together/)에 따르면, Ando 창업자 Sara Du는 기존 플랫폼이 에이전트를 "설치된 앱"으로만 취급해서 인간이 에이전트 출력을 동료에게 수동으로 전달하는 "고기 프록시" 문제가 생긴다고 지적했어요. Ando는 그 병목을 없앤 구조예요.

## 3. 덜 가능성 높지만 놓치면 안 되는 변수

- **Jack Dorsey의 Buzz 플랫폼:** 개발자 특화 에이전트 메시징 도구. 지금은 개발팀 내부 이슈처럼 보이지만, 채택 속도가 빠르면 IT 인프라 범위가 달라져요
- **Microsoft Teams Copilot 연동:** Teams에 깊이 통합된 Copilot이 Slack 없이 같은 기능을 제공하는 환경이라면, 도구 전환 결정이 IT 담당자 역할에 직접 영향을 줘요
- **AI 에이전트 권한 범위 설정 미비:** 에이전트가 어디까지 접근하는지 명확히 정의되지 않으면 보안 감사 때 문제가 생겨요. `Slack 관리 → 데이터 관리 → 앱 권한` 페이지에서 각 에이전트의 스코프를 꼭 확인하세요

## 4. 이래도 답이 안 나온다면

Slack 관련 AI 에이전트 설정 및 권한 이슈는 [Slack Developer Forum](https://forums.slack.com/t5/slack-developer-forum/bd-p/Developer) 또는 Salesforce 공식 지원 포털 `help.salesforce.com`의 Slackbot 카테고리가 가장 빠른 답을 줘요.

질문할 때 반드시 포함할 것:

- Slack 워크스페이스 플랜 (Pro / Business+ / Enterprise Grid)
- 연동된 앱/MCP 서버 목록
- 에러 발생 시 정확한 채널명과 트리거 유형
- 이미 시도해본 설정 변경 내역

공식 문서는 [api.slack.com/docs/apps](https://api.slack.com/docs/apps)에서 에이전트 권한 설정 부분을 먼저 읽어보세요.

## 5. IT 담당자가 지금 해야 할 한 가지

"대체되느냐"가 아니라 "무엇을 넘겨줄 수 있느냐"가 진짜 질문이에요.

반복 티켓 처리, 계정 관리 루틴, 온보딩 체크리스트. 이 세 가지를 Slackbot 워크플로우로 넘겨두면 IT 담당자는 더 복잡한 인프라 판단에 집중할 수 있어요. Salesforce 내부에서 Slackbot 헤비 유저는 주당 20시간을 돌려받았거든요. 주당 20시간이면 한 달에 꼬박 이틀이에요.

지금 당장 한 가지만 하세요. IT 채널에서 지난 30일간 가장 많이 반복된 요청 유형 세 개를 꺼내서, 그 중 하나만 워크플로우 빌더로 자동화해보세요. 그게 시작이에요.
